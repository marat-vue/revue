# Что такое пул соединений `pg`?

> [!NOTE]
> Пул хранит несколько готовых соединений с PostgreSQL и выдаёт их запросам по очереди. Это быстрее и безопаснее, чем открывать новое соединение для каждого HTTP-запроса.

## Вопрос

Что такое пул соединений `pg` и как его настраивать? Когда нужен `pool.connect()` вместо `pool.query()`?

## Почему соединение не создают каждый раз

Открытие соединения требует:

- сетевого обмена;
- проверки пользователя;
- настройки защищённого соединения;
- ресурсов Node.js и PostgreSQL.

Пул повторно использует уже открытые соединения.

```text
HTTP-запросы:  A  B  C  D  E
                    ↓
Пул:          [1] [2] [3]
                    ↓
PostgreSQL
```

Если все соединения заняты, следующий запрос ждёт освобождения одного из них.

## Короткий запрос

```ts
const result = await pool.query<UserRow>(
  "SELECT id, name, email FROM users ORDER BY id",
);
```

`pool.query()` самостоятельно берёт соединение и возвращает его после запроса.

## Ручное получение соединения

```ts
const client = await pool.connect();

try {
  const result = await client.query("SELECT 1");
  console.log(result.rows);
} finally {
  client.release();
}
```

`release()` должен выполняться в `finally`. Иначе соединение навсегда останется занятым, а очередь начнёт расти.

## Размер пула

Больше соединений не всегда быстрее. PostgreSQL тратит ресурсы на каждое соединение, а приложение может работать в нескольких процессах:

```text
4 процесса × pool.max 10 = до 40 соединений
```

Начинай с небольшого значения и учитывай ограничение базы, число процессов и характер запросов.

## Важные настройки

| Настройка | Значение |
|---|---|
| `max` | Максимум соединений в пуле |
| `connectionTimeoutMillis` | Сколько ждать открытия соединения |
| `idleTimeoutMillis` | Когда закрывать долго неиспользуемое соединение |

## Долгие запросы

Один медленный запрос удерживает соединение и уменьшает доступную ёмкость пула. Нужны:

- индексы;
- ограничение времени запроса;
- наблюдение за медленными запросами;
- разумная пагинация.

## Что важно помнить

- `pool.query()` сам берёт и возвращает соединение — подходит для одиночного запроса.
- `pool.connect()` нужен, когда несколько команд должны идти через одно соединение, например транзакция.
- Полученный `client` освобождается в `finally` через `client.release()`, иначе пул «утекает».
- Размер пула × число процессов не должен превышать `max_connections` базы.
- Долгие запросы ограничивают через `statement_timeout`, а ожидание соединения — через `connectionTimeoutMillis`.

## Мини-шпаргалка

- Пул повторно использует соединения.
- Для одного запроса удобен `pool.query()`.
- Транзакция требует `pool.connect()`.
- Полученное соединение всегда освобождается в `finally`.
- Размер пула согласуется с ограничениями базы и числом процессов.
