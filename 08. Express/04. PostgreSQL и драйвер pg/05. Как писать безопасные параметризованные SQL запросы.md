# Как писать безопасные параметризованные SQL-запросы?

> [!NOTE]
> Пользовательские значения нельзя вставлять в SQL через конкатенацию или шаблонную строку. Передавай SQL отдельно, а значения — отдельным массивом параметров.

## Вопрос

Как писать безопасные параметризованные SQL-запросы через `pg`? Почему конкатенация строк опасна?

## Опасный запрос

```ts
const email = request.query.email;

const result = await pool.query(
  `SELECT * FROM users WHERE email = '${email}'`,
);
```

Злоумышленник может изменить смысл SQL. Это называется SQL-инъекцией.

## Параметризованный запрос

```ts
const result = await pool.query<UserRow>(
  "SELECT id, name, email FROM users WHERE email = $1",
  [email],
);
```

`$1`, `$2` и последующие обозначения заменяются значениями средствами драйвера и PostgreSQL. Значение остаётся данными и не становится частью SQL-команды.

## Вставка

```ts
const result = await pool.query<UserRow>(
  `
    INSERT INTO users (name, email)
    VALUES ($1, $2)
    RETURNING id, name, email, created_at
  `,
  [input.name, input.email],
);
```

`RETURNING` сразу возвращает созданную строку.

## Параметры не заменяют имена таблиц и столбцов

Так не сработает:

```sql
SELECT * FROM users ORDER BY $1
```

Для динамической сортировки используй белый список:

```ts
const columns = {
  name: "name",
  createdAt: "created_at",
} as const;

const column = columns[input.sort];

const result = await pool.query(
  `SELECT id, name FROM users ORDER BY ${column} DESC`,
);
```

В строку попадает только значение, выбранное самим сервером.

## Параметры и `LIKE`

```ts
const result = await pool.query<UserRow>(
  `
    SELECT id, name, email
    FROM users
    WHERE name ILIKE $1
    LIMIT $2
  `,
  [`%${search}%`, limit],
);
```

Это безопасно от SQL-инъекции, потому что вся поисковая строка остаётся одним параметром.

## Что важно помнить

- Значения передаются массивом, плейсхолдеры `$1`, `$2` нумеруются с единицы.
- Параметры работают только для значений — имена таблиц и столбцов выбираются из белого списка.
- Для `LIKE` знак `%` добавляется к значению параметра, а не вставляется в текст SQL.
- Шаблонная строка `${value}` в SQL — та же конкатенация и та же SQL-инъекция.

## Мини-шпаргалка

- Значения передаются отдельным массивом.
- `$1` обозначает первый параметр, `$2` — второй.
- Не собирай SQL из пользовательских строк.
- Имена столбцов выбираются только из белого списка.
- `RETURNING` возвращает вставленную или изменённую строку.
