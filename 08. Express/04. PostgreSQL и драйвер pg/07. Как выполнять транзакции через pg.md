# Как выполнять транзакции через `pg`?

> [!NOTE]
> Транзакция объединяет несколько SQL-команд в одно целое: либо выполняются все команды, либо не сохраняется ни одна. Все команды транзакции должны использовать одно соединение.

## Вопрос

Как выполнить транзакцию через `pg`? Почему все команды транзакции должны идти через один `client`?

## Пример перевода денег

Нужно уменьшить баланс одного счёта и увеличить баланс другого. Половина операции недопустима.

```ts
const client = await pool.connect();

try {
  await client.query("BEGIN");

  const withdrawResult = await client.query(
    `
      UPDATE accounts
      SET balance = balance - $1
      WHERE id = $2 AND balance >= $1
    `,
    [amount, fromAccountId],
  );

  if (withdrawResult.rowCount !== 1) {
    throw new Error("Недостаточно средств или счёт не найден");
  }

  const depositResult = await client.query(
    `
      UPDATE accounts
      SET balance = balance + $1
      WHERE id = $2
    `,
    [amount, toAccountId],
  );

  if (depositResult.rowCount !== 1) {
    throw new Error("Счёт получателя не найден");
  }

  await client.query("COMMIT");
} catch (error) {
  await client.query("ROLLBACK");
  throw error;
} finally {
  client.release();
}
```

## Почему нельзя использовать `pool.query()`

```ts
// Неправильно для транзакции
await pool.query("BEGIN");
await pool.query("UPDATE ...");
await pool.query("COMMIT");
```

Каждый вызов может получить другое соединение. `BEGIN` действует только внутри соединения, на котором он был выполнен.

## Короткая транзакция

Не выполняй внутри транзакции:

- запрос к внешнему API;
- отправку письма;
- долгий расчёт;
- ожидание действия пользователя.

Пока транзакция открыта, база удерживает ресурсы и, возможно, блокировки.

## Ошибка после `COMMIT`

После успешного `COMMIT` данные уже сохранены. Если затем не удалось отправить письмо, откатить транзакцию поздно. Такие внешние действия планируют отдельно, например через очередь и таблицу событий.

## Что важно помнить

- `pool.query()` может отправить каждую команду через разное соединение — транзакция развалится.
- Схема: `BEGIN` → команды → `COMMIT`, при ошибке — `ROLLBACK`, в `finally` — `client.release()`.
- Внутри транзакции не делают долгих внешних вызовов: соединение и блокировки удерживаются всё это время.
- Ошибку после `COMMIT` уже нельзя откатить — данные сохранены.

## Мини-шпаргалка

- Транзакция: `BEGIN → команды → COMMIT`.
- При ошибке выполняется `ROLLBACK`.
- Все команды используют один `client`.
- Соединение освобождается в `finally`.
- Транзакция должна быть как можно короче.
