# Какие типы и результаты возвращает `pg`?

> [!NOTE]
> Результат `pg` содержит массив `rows`, число затронутых строк и служебные сведения. Некоторые типы PostgreSQL намеренно возвращаются строками, чтобы JavaScript не потерял точность.

## Вопрос

Какие данные и типы возвращает `pg`? Почему `bigint`, `numeric` и `COUNT(*)` приходят строками?

## Результат запроса

```ts
const result = await pool.query<UserRow>(
  "SELECT id, name FROM users",
);

console.log(result.rows);
console.log(result.rowCount);
console.log(result.command);
```

| Поле | Значение |
|---|---|
| `rows` | Полученные строки |
| `rowCount` | Число обработанных строк или `null` |
| `command` | Например `SELECT`, `INSERT`, `UPDATE` |
| `fields` | Описание столбцов результата |

Тип `UserRow` помогает TypeScript, но не проверяет ответ базы во время работы. Он должен соответствовать настоящему SQL.

## Важные преобразования

| PostgreSQL | JavaScript в `pg` |
|---|---|
| `integer` | `number` |
| `bigint` | обычно `string` |
| `numeric` | обычно `string` |
| `boolean` | `boolean` |
| `text`, `varchar` | `string` |
| `timestamp`, `timestamptz`, `date` | `Date` |
| `json`, `jsonb` | объект или массив |
| `bytea` | `Buffer` |
| `NULL` | `null` |

`bigint` и `numeric` могут превышать безопасную точность JavaScript, поэтому драйвер не всегда превращает их в `number`.

## `COUNT(*)`

```ts
const result = await pool.query<{ count: string }>(
  "SELECT count(*) AS count FROM users",
);

const total = Number(result.rows[0]?.count ?? 0);
```

Преобразуй значение только если уверен, что оно помещается в безопасный диапазон.

## Даты

Для моментов времени обычно выбирают `timestamptz` и передают клиенту ISO-строку:

```ts
const value = row.created_at.toISOString();
```

Не смешивай момент времени с календарной датой вроде дня рождения, где часовой пояс может быть не нужен.

## Ошибки PostgreSQL

Ошибка базы часто имеет поле `code`:

```ts
function hasDatabaseCode(error: unknown): error is Error & { code: string } {
  return error instanceof Error && "code" in error;
}

try {
  await insertUser(input);
} catch (error) {
  if (hasDatabaseCode(error) && error.code === "23505") {
    throw new AppError(409, "EMAIL_ALREADY_EXISTS", "Почта уже занята");
  }

  throw error;
}
```

Частые коды:

| Код | Причина |
|---|---|
| `23505` | Нарушена уникальность |
| `23503` | Нарушен внешний ключ |
| `23502` | В обязательное поле передан `NULL` |
| `22P02` | Неверный формат значения |

## Что важно помнить

- Строки результата лежат в `result.rows`, число затронутых строк — в `result.rowCount`.
- `bigint` и `numeric` возвращаются строками, чтобы не потерять точность в `number`.
- `COUNT(*)` имеет тип `bigint` — результат нужно преобразовать или привести в SQL (`::int`).
- `timestamptz` превращается в `Date`; `NULL` — в `null`.
- Код ошибки PostgreSQL (`23505` — нарушение уникальности) позволяет вернуть `409` вместо `500`.

## Мини-шпаргалка

- Строки находятся в `result.rows`.
- `rowCount` показывает число затронутых строк.
- `bigint`, `numeric` и `COUNT(*)` часто приходят строками.
- `NULL` становится `null`.
- Код PostgreSQL позволяет превратить техническую ошибку в понятный HTTP-ответ.
