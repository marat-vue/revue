# Как управлять зависимостями и конфигурацией?

> [!NOTE]
> Модули не должны самостоятельно читать случайные переменные окружения и создавать новые пулы. Конфигурация проверяется один раз, а общие зависимости создаются в одном месте.

## Вопрос

Как управлять конфигурацией и зависимостями в Express-приложении без специального DI-контейнера?

## Плохой вариант

```ts
// Каждый модуль создаёт своё соединение и читает окружение.
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});
```

Проблемы:

- несколько пулов;
- разные настройки;
- сложные тесты;
- ошибка конфигурации проявляется поздно.

## Единая конфигурация

```ts
// config/env.ts
export const env = envSchema.parse(process.env);
```

```ts
// db/index.ts
export const pool = new Pool({
  connectionString: env.DATABASE_URL,
});

export const db = drizzle({ client: pool, schema });
```

Остальные модули импортируют готовую зависимость.

## Простое внедрение зависимости

Для удобного модульного теста службу можно сделать фабрикой:

```ts
type UsersRepository = {
  findByEmail(email: string): Promise<User | undefined>;
  insert(input: CreateUserInput): Promise<User>;
};

export function createUsersService(repository: UsersRepository) {
  return {
    async create(input: CreateUserInput) {
      const existingUser = await repository.findByEmail(input.email);

      if (existingUser) {
        throw new AppError(409, "EMAIL_EXISTS", "Почта уже занята");
      }

      return repository.insert(input);
    },
  };
}
```

В приложении передаётся настоящий репозиторий, в тесте — управляемая реализация в памяти.

## Не нужен специальный контейнер

В небольшом проекте достаточно обычных импортов и функций-фабрик. Сложная система внедрения зависимостей нужна только при настоящей сложности.

## Время создания зависимости

- конфигурация проверяется при старте;
- пул создаётся один раз на процесс;
- лёгкая служба может создаваться один раз;
- данные конкретного запроса не хранятся в общей переменной.

## Что важно помнить

- Окружение проверяется один раз в модуле конфигурации, остальной код импортирует готовый `env`.
- Пул и экземпляр Drizzle создаются в одном месте и передаются дальше.
- Фабрика `createUsersService(repository)` позволяет подменить репозиторий в тесте.
- Для небольшого API ручная передача зависимостей проще, чем библиотека-контейнер.

## Мини-шпаргалка

- Проверяй окружение один раз при запуске.
- Создавай один пул на процесс.
- Не читай `process.env` во всех файлах подряд.
- Фабрика помогает заменить репозиторий в тесте.
- Не добавляй сложную инфраструктуру без необходимости.
