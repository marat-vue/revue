# Какие базовые меры безопасности нужны Express API?

> [!NOTE]
> Безопасность складывается из нескольких слоёв: проверка данных, ограничения PostgreSQL, права доступа, безопасные заголовки, HTTPS, лимиты и аккуратная работа с секретами.

## Вопрос

Какие базовые меры безопасности нужны Express API: заголовки, лимиты, CSRF, прокси, загрузка файлов?

## Защитные заголовки

```bash
npm install helmet
```

```ts
import helmet from "helmet";

app.use(helmet());
app.disable("x-powered-by");
```

Helmet устанавливает набор защитных HTTP-заголовков. Некоторые правила, особенно политика загрузки содержимого, нужно согласовать с устройством приложения.

## Ограничение размера тела

```ts
app.use(express.json({ limit: "100kb" }));
app.use(express.urlencoded({ extended: false, limit: "50kb" }));
```

## Ограничение частоты

```bash
npm install express-rate-limit
```

```ts
import { rateLimit } from "express-rate-limit";

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 20,
  standardHeaders: true,
  legacyHeaders: false,
});

app.use("/api/auth/login", loginLimiter);
```

В нескольких процессах нужен общий хранитель счётчиков. Значения лимита выбираются по настоящей нагрузке и риску.

## Основной список

- проверяй `params`, `query` и `body`;
- используй параметры SQL или Drizzle;
- проверяй пользователя, роль и владельца ресурса;
- не возвращай секретные столбцы;
- используй HTTPS;
- ограничивай размер тела и число запросов;
- обновляй зависимости;
- не раскрывай стек и SQL в ответе;
- используй отдельного пользователя PostgreSQL с нужными, но не избыточными правами.

## CSRF

Если браузер автоматически отправляет cookie авторизации, опасный запрос может быть вызван с чужого сайта. `SameSite` снижает риск, но для некоторых схем нужны отдельный CSRF-токен и строгая проверка источника.

CORS не является полной защитой от CSRF и не заменяет авторизацию.

## Обратный прокси

Если Express находится за доверенным прокси, настрой `trust proxy` согласно настоящему числу и типу прокси:

```ts
app.set("trust proxy", 1);
```

Не копируй это значение без понимания инфраструктуры: оно влияет на IP клиента, защищённость соединения и работу ограничителей.

## Загрузка файлов

При загрузке файла нужно отдельно ограничить:

- размер;
- число файлов;
- допустимые типы;
- место хранения;
- имя файла;
- доступ к загруженному содержимому.

Одного расширения имени недостаточно для определения типа.

## Что важно помнить

- Helmet добавляет защитные заголовки одной строкой, но не заменяет остальные меры.
- Лимит частоты ставят прежде всего на вход, регистрацию и восстановление пароля.
- При cookie-аутентификации нужна защита от CSRF: `sameSite`, проверка `Origin` или токен.
- `trust proxy` включают только с известным числом прокси, иначе клиент подделает IP через `X-Forwarded-For`.
- Загруженные файлы проверяют по размеру и типу и не сохраняют под именем, которое прислал клиент.

## Мини-шпаргалка

- Helmet добавляет защитные заголовки.
- Ограничивай размер тела и частоту чувствительных запросов.
- CORS не заменяет права доступа и защиту от CSRF.
- Параметризованный SQL защищает от инъекций значений.
- `trust proxy` настраивается только под известную инфраструктуру.
