# Как устроены аутентификация и авторизация?

> [!NOTE]
> Аутентификация отвечает на вопрос «кто это?», а авторизация — «что этому пользователю разрешено?». Сервер обязан выполнять обе проверки сам.

## Вопрос

Чем аутентификация отличается от авторизации? Как хранить пароли и передавать сессию между Vue и Express?

## Обычный вход

```text
почта + пароль
      ↓
поиск пользователя
      ↓
проверка хеша пароля
      ↓
создание сессии или токена
      ↓
защищённый запрос
      ↓
проверка пользователя и прав
```

## Пароли

Пароль нельзя хранить открытым текстом или шифровать обратимым способом. Для нового приложения выбирают алгоритм хранения паролей, например Argon2id.

```bash
npm install argon2
```

```ts
import argon2 from "argon2";

const passwordHash = await argon2.hash(password, {
  type: argon2.argon2id,
});

const isCorrect = await argon2.verify(passwordHash, password);
```

Библиотека сама хранит соль и параметры внутри строки хеша. Параметры нужно проверять на своём сервере и периодически пересматривать.

## Сессия и токен

| Подход | Где состояние |
|---|---|
| Серверная сессия | В хранилище сервера, браузер хранит случайный идентификатор |
| JWT | Основные сведения подписаны внутри токена |

Для обычного сайта серверная сессия часто проще отзывается и обновляется. JWT полезен не потому, что он «современнее», а когда его свойства действительно нужны архитектуре.

Стандартное хранилище памяти `express-session` не подходит для рабочего многопроцессного приложения. Нужен внешний хранитель сессий.

## Защищённый cookie

```ts
response.cookie("session", sessionId, {
  httpOnly: true,
  secure: env.NODE_ENV === "production",
  sameSite: "lax",
  maxAge: 1000 * 60 * 60 * 24 * 7,
});
```

- `httpOnly` запрещает JavaScript страницы читать cookie;
- `secure` отправляет его только по HTTPS;
- `sameSite` ограничивает межсайтовую отправку;
- срок жизни должен быть конечным.

## Проверка владельца

Недостаточно просто войти:

```ts
if (task.userId !== request.user.id) {
  throw new AppError(403, "FORBIDDEN", "Нет доступа к задаче");
}
```

Скрытая кнопка во Vue не является защитой. Запрос можно отправить напрямую.

## Что важно помнить

- Пароли хранят медленным хешем (argon2, bcrypt), а не шифрованием и не быстрым SHA.
- Cookie с сессией ставят с флагами `httpOnly`, `secure` и `sameSite`.
- Проверка владельца записи (`task.userId === currentUser.id`) выполняется на сервере в каждом запросе.
- Скрытая кнопка во Vue не защищает действие — права проверяет только API.
- `401` — пользователь не вошёл, `403` — вошёл, но прав нет.

## Мини-шпаргалка

- Аутентификация подтверждает личность.
- Авторизация проверяет права.
- Пароль хранится как медленный стойкий хеш.
- `httpOnly` защищает cookie от чтения JavaScript.
- Все права проверяются на сервере, а не только в интерфейсе.
