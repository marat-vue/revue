# Как добавить журнал запросов, проверку состояния и корректную остановку?

> [!NOTE]
> Рабочий сервер должен позволять связать ошибку с запросом, сообщать о готовности и закрывать HTTP-сервер вместе с пулом PostgreSQL.

## Вопрос

Как добавить в Express журнал запросов, проверки состояния и корректную остановку сервера?

## Идентификатор запроса

```ts
import { randomUUID } from "node:crypto";
import type { RequestHandler } from "express";

export const requestContext: RequestHandler = (
  request,
  response,
  next,
) => {
  const requestId = request.get("x-request-id") ?? randomUUID();
  response.set("x-request-id", requestId);

  const startedAt = performance.now();

  response.on("finish", () => {
    console.log({
      requestId,
      method: request.method,
      path: request.path,
      status: response.statusCode,
      durationMs: Math.round(performance.now() - startedAt),
    });
  });

  next();
};
```

В рабочем приложении обычно используют библиотеку структурированных журналов, но набор полей остаётся похожим.

Не записывай пароли, токены, cookie и полные личные данные.

## Проверки состояния

```ts
app.get("/health/live", (request, response) => {
  response.json({ status: "ok" });
});

app.get("/health/ready", async (request, response) => {
  await pool.query("SELECT 1");
  response.json({ status: "ready" });
});
```

- `live` показывает, что процесс отвечает;
- `ready` показывает, что он готов обслуживать запросы и видит обязательные зависимости.

Не превращай проверку в тяжёлый запрос.

## Корректная остановка

```ts
const server = app.listen(env.PORT);

async function shutdown(signal: string) {
  console.log({ message: "Остановка сервера", signal });

  server.close(async (serverError) => {
    try {
      await pool.end();
      process.exitCode = serverError ? 1 : 0;
    } catch (databaseError) {
      console.error(databaseError);
      process.exitCode = 1;
    }
  });
}

process.once("SIGTERM", () => void shutdown("SIGTERM"));
process.once("SIGINT", () => void shutdown("SIGINT"));
```

Нужен и предельный срок остановки, чтобы процесс не ждал зависший запрос бесконечно. Его значение зависит от ограничений окружения.

## Что важно помнить

- Идентификатор запроса (`x-request-id`) связывает записи журнала и ответ клиенту.
- Журнал пишут структурированно (JSON) — метод, путь, статус, длительность, без паролей и токенов.
- `/health/live` отвечает, жив ли процесс, `/health/ready` — готовы ли зависимости, например база.
- При `SIGTERM` сначала закрывают HTTP-сервер, затем пул PostgreSQL.

## Мини-шпаргалка

- Идентификатор связывает записи одного запроса.
- Журнал содержит метод, путь, статус и длительность.
- `live` проверяет процесс, `ready` — готовность зависимостей.
- При остановке закрываются HTTP-сервер и пул.
- Секреты и пароли не попадают в журнал.
