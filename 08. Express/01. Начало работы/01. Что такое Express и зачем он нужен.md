# Что такое Express и зачем он нужен?

> [!NOTE]
> Express — небольшой веб-фреймворк для Node.js. Он помогает сопоставлять HTTP-запросы с функциями, читать данные запроса и формировать ответ.

## Вопрос

Что такое Express и какие задачи он решает поверх `node:http`? Чего Express не делает сам?

## Основная идея

На чистом `node:http` разработчику приходится самостоятельно разбирать адрес, метод и тело запроса. Express предоставляет для этого удобные методы.

```ts
app.get("/api/users", (request, response) => {
  response.json([{ id: 1, name: "Анна" }]);
});
```

Этот код означает:

```text
Если пришёл GET-запрос на /api/users,
выполни функцию и верни массив в формате JSON.
```

## Что делает Express

- выбирает обработчик по методу и адресу;
- извлекает параметры адреса;
- разбирает JSON в теле запроса;
- выстраивает цепочку промежуточных обработчиков;
- помогает задавать код, заголовки и тело ответа;
- передаёт ошибки общему обработчику;
- позволяет разбить маршруты по отдельным файлам.

## Чего Express не делает сам

Express не является:

- базой данных;
- ORM;
- средством проверки входных данных;
- системой авторизации;
- готовой архитектурой проекта;
- средством выполнения фоновых задач.

Для этих задач подключаются отдельные библиотеки или пишется собственный код.

## Express не заменяет знания HTTP

За методами Express скрываются обычные HTTP-понятия:

| Express | HTTP |
|---|---|
| `app.get()` | Метод `GET` |
| `request.headers` | Заголовки запроса |
| `response.status(201)` | Код ответа |
| `response.json(data)` | JSON в теле ответа |
| `request.params.id` | Часть адреса |

## Когда Express подходит

- небольшой или средний REST API;
- сервер для Vue-приложения;
- внутренний служебный API;
- учебный проект;
- приложение, которому нужна свободная архитектура.

Если нужна полностью готовая архитектура с большим количеством встроенных правил, можно рассмотреть NestJS. Для небольшой прослойки между интерфейсом и базой Express проще.

## Что важно помнить

- Express — тонкий слой над HTTP-сервером Node.js: без понимания методов, заголовков и статус-кодов работать с ним сложно.
- Фреймворк не навязывает структуру проекта — архитектуру, проверку данных и работу с базой выбирает команда.
- Для небольшого API или прослойки между Vue и базой Express проще NestJS; для большой команды с жёсткими правилами NestJS даёт больше готового.
- Express 5 — актуальная версия: асинхронные ошибки обработчиков передаются дальше автоматически.

## Мини-шпаргалка

- Express работает поверх HTTP-сервера Node.js.
- Маршрут связывает метод и адрес с функцией.
- Express остаётся небольшим и не навязывает архитектуру.
- База данных и проверка данных подключаются отдельно.
- Чтобы уверенно работать с Express, нужно понимать основы HTTP.
