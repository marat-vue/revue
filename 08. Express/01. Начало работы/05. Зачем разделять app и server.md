# Зачем разделять `app` и `server`?

> [!NOTE]
> Файл `app.ts` собирает Express-приложение, а `server.ts` подключает окружение, открывает порт и управляет жизненным циклом процесса. Такое разделение упрощает тестирование и остановку сервера.

## Вопрос

Зачем разделять Express-приложение на `app.ts` и `server.ts`? Как это помогает тестам и остановке сервера?

## `src/app.ts`

```ts
import express from "express";

export const app = express();

app.use(express.json({ limit: "100kb" }));

app.get("/api/health", (request, response) => {
  response.json({ status: "ok" });
});
```

Здесь нет `listen()`. Файл только создаёт и настраивает приложение.

## `src/server.ts`

```ts
import "dotenv/config";
import { app } from "./app.js";

const port = Number(process.env.PORT ?? 3000);

const server = app.listen(port, () => {
  console.log(`Сервер запущен: http://localhost:${port}`);
});

function shutdown(signal: string) {
  console.log(`Получен сигнал ${signal}`);

  server.close((error) => {
    if (error) {
      console.error(error);
      process.exitCode = 1;
      return;
    }

    process.exitCode = 0;
  });
}

process.on("SIGTERM", () => shutdown("SIGTERM"));
process.on("SIGINT", () => shutdown("SIGINT"));
```

## Почему так удобнее тестировать

Проверка может импортировать `app` и отправлять запросы без настоящего сетевого порта:

```ts
import request from "supertest";
import { app } from "./app.js";

const response = await request(app).get("/api/health");
```

Если `listen()` выполняется при импорте, каждый тест пытается открыть порт, и завершать процесс становится сложнее.

## Более крупная структура

```text
src/
├── app.ts
├── server.ts
├── config/
├── db/
├── middleware/
└── modules/
    └── users/
        ├── users.routes.ts
        ├── users.controller.ts
        ├── users.service.ts
        └── users.repository.ts
```

Не нужно создавать все слои для двух маршрутов. Разделяй проект по мере появления настоящей сложности.

## Что важно помнить

- `app.ts` не должен вызывать `listen()` — тогда его можно импортировать в тесты без открытия порта.
- `server.ts` отвечает за окружение, порт и сигналы `SIGTERM` / `SIGINT`.
- `server.close()` перестаёт принимать новые соединения и дожидается текущих запросов.
- Слои и папки добавляются по мере роста проекта, а не заранее.

## Мини-шпаргалка

- `app.ts` собирает Express-приложение.
- `server.ts` открывает порт.
- Приложение без `listen()` проще тестировать.
- `server.close()` перестаёт принимать новые соединения.
- Сложность структуры должна соответствовать размеру проекта.
