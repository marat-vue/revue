# Как собрать учебный проект Express, PostgreSQL и Drizzle?

> [!NOTE]
> Собери один небольшой API пользователей и задач. В нём должны быть проверка входа, миграции, связи, ошибки, тесты и вызов из Vue.

## Вопрос

Как собрать учебный проект на Express, PostgreSQL и Drizzle, который не стыдно показать на собеседовании?

## Возможности проекта

- создать пользователя;
- получить список и одного пользователя;
- изменить имя;
- удалить пользователя;
- создать задачу пользователя;
- получить пользователя вместе с задачами;
- запретить повторную почту;
- вернуть понятную ошибку для неверных данных.

## Зависимости

```bash
npm install express cors dotenv helmet express-rate-limit zod
npm install drizzle-orm pg
npm install --save-dev \
  typescript tsx \
  @types/node @types/express @types/cors @types/pg \
  drizzle-kit vitest supertest @types/supertest
```

## Порядок реализации

1. Запусти PostgreSQL.
2. Создай Express-проект и `/api/health`.
3. Проверь конфигурацию через Zod.
4. Опиши `users` и `tasks` в Drizzle.
5. Создай и прочитай первую миграцию.
6. Примени миграцию к локальной базе.
7. Напиши репозитории.
8. Добавь службы и прикладные ошибки.
9. Подключи контроллеры и маршруты.
10. Добавь CORS, Helmet и ограничения.
11. Проверь запросы через Postman.
12. Напиши модульные и интеграционные тесты.
13. Подключи Vue через общую функцию `apiRequest`.

## Минимальные проверки

```text
[ ] POST /users возвращает 201
[ ] неверная почта возвращает 400
[ ] повторная почта возвращает 409
[ ] неизвестный пользователь возвращает 404
[ ] задача с неизвестным userId запрещена
[ ] удаление пользователя обрабатывает связанные задачи по выбранному правилу
[ ] список имеет limit
[ ] миграции применяются к пустой базе
[ ] сервер закрывает пул при остановке
```

## Что важно помнить

- Начинают со схемы данных и договора API, а не с файлов и папок.
- Миграции, проверка входа, обработчик ошибок и тесты входят в первую версию.
- API проверяют через `curl` или Postman отдельно от Vue.
- README с командами запуска, переменными окружения и примерами запросов — часть результата.

## Мини-шпаргалка

- Один законченный CRUD полезнее десяти пустых заготовок.
- Начинай со схемы данных и договора API.
- Миграции и тесты входят в проект, а не добавляются «когда-нибудь».
- Проверяй API отдельно от Vue.
- Документация запуска является частью результата.
