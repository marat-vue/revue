# Какие ошибки часто допускают начинающие в Express?

> [!NOTE]
> Большинство первых ошибок связано не с синтаксисом Express, а с доверием внешним данным, смешением ответственностей и неправильным управлением базой.

## Вопрос

Какие ошибки чаще всего допускают начинающие в Express, PostgreSQL и Drizzle и как их избежать?

## Express и HTTP

- `express.json()` подключён после маршрутов;
- после отправки ошибки код продолжает работу;
- один запрос пытается отправить два ответа;
- middleware не вызывает `next()` и не отвечает;
- обработчик ошибок размещён до маршрутов;
- любой сбой возвращается с кодом `200`;
- `401`, `403` и `404` используются как одно и то же;
- `request.body` приводится через `as`, но не проверяется.

## PostgreSQL

- пул создаётся внутри каждого запроса;
- SQL собирается из пользовательской строки;
- соединение после `pool.connect()` не освобождается;
- транзакция выполняется через несколько `pool.query()`;
- приложение полагается на проверку уникальности без `UNIQUE`;
- список возвращается без `LIMIT`;
- удаление и изменение выполняются без `WHERE`;
- рабочая база используется в тестах.

## Drizzle

- изменения `schema.ts` считают уже применёнными к базе;
- миграция создаётся, но её SQL никто не читает;
- `push` бесконтрольно запускается в рабочем окружении;
- `request.body` целиком передаётся в `.set()`;
- выбираются все столбцы, включая секретные;
- связи описаны в ORM, но внешний ключ не создан;
- не замечается N + 1.

## Архитектура

- всё приложение находится в одном файле;
- контроллер содержит большой SQL и прикладные правила;
- создаются слои, которые только передают вызов дальше;
- ошибки базы отправляются клиенту целиком;
- пароль или токен попадает в журнал;
- права проверяются только скрытием кнопки во Vue;
- конфигурация читается по-разному в каждом модуле.

## Что важно помнить

- Использование `request.body` без проверки — главный источник багов и уязвимостей.
- Пул в каждом запросе и забытый `client.release()` исчерпывают соединения.
- SQL из шаблонных строк открывает SQL-инъекции.
- `drizzle-kit push` на общей базе вместо миграций теряет историю изменений.
- Вся логика в файле маршрутов делает код сложным для тестов и изменений.

## Мини-шпаргалка

- Не доверяй данным клиента.
- Не создавай пул на каждый запрос.
- Не выполняй SQL-конкатенацию.
- Не путай схему Drizzle с миграцией и проверкой Zod.
- Уверенный уровень подтверждается законченным проектом и объяснением решений.
