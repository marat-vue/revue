# Как собрать `app` и `server` в готовом проекте?

> [!NOTE]
> В итоговом приложении `app.ts` задаёт порядок промежуточных обработчиков и маршрутов, а `server.ts` проверяет базу, открывает порт и корректно закрывает ресурсы.

## Вопрос

Как собрать `app.ts` и `server.ts` в готовом Express-проекте? В каком порядке подключать middleware и ресурсы?

## `app.ts`

```ts
import cors from "cors";
import express from "express";
import helmet from "helmet";
import { env } from "./config/env.js";
import { errorHandler } from "./middleware/error-handler.js";
import { notFoundHandler } from "./middleware/not-found-handler.js";
import { usersRouter } from "./modules/users/users.routes.js";

export const app = express();

app.disable("x-powered-by");
app.use(helmet());
app.use(
  cors({
    origin: env.CLIENT_ORIGIN,
    credentials: true,
  }),
);
app.use(express.json({ limit: "100kb" }));

app.get("/health/live", (request, response) => {
  response.json({ status: "ok" });
});

app.use("/api/users", usersRouter);

app.use(notFoundHandler);
app.use(errorHandler);
```

## `server.ts`

```ts
import { app } from "./app.js";
import { env } from "./config/env.js";
import { pool } from "./db/index.js";

await pool.query("SELECT 1");

const server = app.listen(env.PORT, () => {
  console.log(`Сервер запущен: http://localhost:${env.PORT}`);
});

let isShuttingDown = false;

async function shutdown(signal: string) {
  if (isShuttingDown) return;
  isShuttingDown = true;

  console.log({ message: "Остановка", signal });

  server.close(async (serverError) => {
    try {
      await pool.end();
      process.exitCode = serverError ? 1 : 0;
    } catch (error) {
      console.error(error);
      process.exitCode = 1;
    }
  });
}

process.once("SIGTERM", () => void shutdown("SIGTERM"));
process.once("SIGINT", () => void shutdown("SIGINT"));
```

## Почему порядок именно такой

```text
защитные заголовки
→ CORS
→ разбор JSON
→ служебные маршруты
→ API
→ 404
→ ошибки
```

Обработчик ошибок должен видеть ошибки всех предыдущих обработчиков.

## Что ещё потребуется в рабочем окружении

- HTTPS и обратный прокси;
- структурированный журнал;
- внешний хранитель сессий, если они используются;
- наблюдение за ошибками и длительностью;
- резервные копии PostgreSQL;
- отдельный шаг миграций;
- предельный срок остановки;
- автоматические проверки перед развёртыванием.

## Что важно помнить

- Порядок в `app.ts`: безопасность и журнал → парсеры → CORS → маршруты → `404` → ошибки.
- `server.ts` проверяет подключение к базе до `listen()`.
- При остановке сначала закрывается HTTP-сервер, затем пул.
- В рабочем окружении добавляются `trust proxy`, HTTPS на прокси и мониторинг.

## Мини-шпаргалка

- `app.ts` не открывает порт.
- `server.ts` проверяет обязательную базу до `listen()`.
- Порядок `app.use()` влияет на поведение.
- `404` идёт после маршрутов, ошибки — последними.
- При остановке закрываются сервер и пул.
