# Что такое middleware и почему важен порядок?

> [!NOTE]
> Middleware — промежуточный обработчик запроса. Он может прочитать или дополнить запрос, изменить ответ, завершить обработку либо передать управление дальше через `next()`.

## Вопрос

Что такое middleware в Express? Где его подключать и почему важен порядок?

## Простой обработчик

```ts
import type { RequestHandler } from "express";

export const requestLogger: RequestHandler = (
  request,
  response,
  next,
) => {
  const startedAt = Date.now();

  response.on("finish", () => {
    console.log({
      method: request.method,
      path: request.path,
      status: response.statusCode,
      durationMs: Date.now() - startedAt,
    });
  });

  next();
};
```

Подключение ко всему приложению:

```ts
app.use(requestLogger);
```

Подключение к одному пути:

```ts
app.use("/api/admin", requireAuth, requireAdmin);
```

Подключение к одному маршруту:

```ts
app.delete("/api/users/:id", requireAuth, deleteUser);
```

## Порядок выполнения

```ts
app.use(requestLogger);
app.use(express.json());
app.use("/api", apiRouter);
app.use(notFoundHandler);
app.use(errorHandler);
```

Порядок читается сверху вниз:

```text
журнал → разбор JSON → маршруты → 404 → ошибка
```

## Когда не нужен `next()`

Если обработчик уже отправил ответ, управление дальше не передаётся:

```ts
const requireApiKey: RequestHandler = (request, response, next) => {
  if (request.get("x-api-key") !== process.env.API_KEY) {
    response.status(401).json({ message: "Неверный ключ" });
    return;
  }

  next();
};
```

## Виды промежуточных обработчиков

- встроенные: `express.json()`, `express.urlencoded()`;
- прикладные: проверка авторизации, роли, владельца записи;
- сторонние: CORS, Helmet, ограничение частоты запросов;
- обработчики маршрутизатора;
- обработчики ошибок.

## Частая ошибка

```ts
app.use((request, response, next) => {
  console.log("Запрос получен");
  // Нет ответа и нет next(). Запрос зависнет.
});
```

## Что важно помнить

- Middleware можно подключить ко всему приложению, к префиксу пути или к одному маршруту.
- Обработчик, который отправил ответ, не вызывает `next()`.
- Middleware без ответа и без `next()` подвешивает запрос до таймаута клиента.
- Для замера длительности используют событие `response.on("finish")` — оно срабатывает после отправки ответа.

## Мини-шпаргалка

- Middleware выполняется по порядку.
- `next()` передаёт управление дальше.
- После отправки ответа `next()` обычно не вызывается.
- Общие обработчики размещаются до маршрутов.
- `404` и ошибки обрабатываются в конце.
