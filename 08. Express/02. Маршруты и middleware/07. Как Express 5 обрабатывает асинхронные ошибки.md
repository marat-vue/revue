# Как Express 5 обрабатывает асинхронные ошибки?

> [!NOTE]
> В Express 5 отклонённый промис из асинхронного обработчика автоматически передаётся обработчику ошибок. Дополнительная обёртка `try/catch` вокруг каждого маршрута обычно не нужна.

## Вопрос

Как Express 5 обрабатывает ошибки в асинхронных обработчиках? Когда всё же нужен `try/catch`?

## Асинхронный маршрут

```ts
app.get("/api/users/:id", async (request, response) => {
  const user = await usersRepository.findById(request.params.id);

  if (!user) {
    throw new Error("Пользователь не найден");
  }

  response.json(user);
});
```

Если `findById()` отклонит промис или код выполнит `throw`, Express 5 передаст ошибку дальше.

## Обработчик ошибок

У него обязательно четыре аргумента:

```ts
import type { ErrorRequestHandler } from "express";

export const errorHandler: ErrorRequestHandler = (
  error,
  request,
  response,
  next,
) => {
  console.error(error);

  response.status(500).json({
    error: {
      code: "INTERNAL_ERROR",
      message: "Внутренняя ошибка сервера",
    },
  });
};
```

Подключение после маршрутов:

```ts
app.use("/api", apiRouter);
app.use(errorHandler);
```

## Когда всё же нужен `try/catch`

`try/catch` нужен, если ошибка обрабатывается именно здесь:

```ts
app.get("/api/report", async (request, response) => {
  try {
    const report = await loadOptionalReport();
    response.json(report);
  } catch (error) {
    response.status(200).json({ data: null, warning: "Отчёт недоступен" });
  }
});
```

Если локально сделать с ошибкой нечего, лучше позволить общему обработчику сформировать ответ.

## Ошибки вне цепочки Express

Express не поймает ошибку, выброшенную позднее в отдельном таймере:

```ts
app.get("/api/example", (request, response, next) => {
  setTimeout(() => {
    try {
      throw new Error("Ошибка таймера");
    } catch (error) {
      next(error);
    }
  }, 10);
});
```

Обычно лучше оборачивать подобные API в промисы и использовать `await`.

## Не отправляй ответ дважды

Если часть ответа уже отправлена, общий обработчик должен передать ошибку встроенному обработчику Express:

```ts
if (response.headersSent) {
  next(error);
  return;
}
```

## Что важно помнить

- В Express 4 отклонённый промис нужно было передавать в `next(error)` вручную или через обёртку — в Express 5 это не нужно.
- Обработчик ошибок распознаётся по четырём аргументам: `(error, request, response, next)`.
- Ошибки в `setTimeout` и колбэках вне цепочки Express передаются через `next(error)` явно.
- Если заголовки уже отправлены (`response.headersSent`), ошибку отдают встроенному обработчику через `next(error)`.

## Мини-шпаргалка

- Express 5 автоматически ловит отклонённые промисы маршрутов.
- Синхронный `throw` также попадает в обработчик ошибок.
- Ошибочный обработчик имеет четыре аргумента.
- `try/catch` нужен для локального восстановления или дополнения ошибки.
- Ошибки таймеров и отдельных обратных вызовов нужно передавать через `next(error)`.
