# Как модульно тестировать службу Express-приложения?

> [!NOTE]
> Службу удобно проверять без HTTP и настоящей базы. Для этого ей передают репозиторий, а тест использует простую управляемую замену.

## Вопрос

Как модульно протестировать службу Express-приложения без HTTP и базы данных?

## Служба с зависимостью

```ts
// src/modules/users/users.service.ts
import { AppError } from "../../errors/app-error.js";

type User = {
  id: number;
  name: string;
  email: string;
};

type UsersRepository = {
  findByEmail(email: string): Promise<User | undefined>;
  insert(input: Omit<User, "id">): Promise<User>;
};

export function createUsersService(repository: UsersRepository) {
  return {
    async create(input: Omit<User, "id">) {
      const existingUser = await repository.findByEmail(input.email);

      if (existingUser) {
        throw new AppError(409, "EMAIL_EXISTS", "Почта уже занята");
      }

      return repository.insert(input);
    },
  };
}
```

## Успешный тест

```ts
import { describe, expect, test, vi } from "vitest";
import { createUsersService } from "../src/modules/users/users.service.js";

describe("usersService.create", () => {
  test("создаёт пользователя со свободной почтой", async () => {
    const repository = {
      findByEmail: vi.fn().mockResolvedValue(undefined),
      insert: vi.fn().mockResolvedValue({
        id: 1,
        name: "Анна",
        email: "anna@example.com",
      }),
    };

    const service = createUsersService(repository);

    const user = await service.create({
      name: "Анна",
      email: "anna@example.com",
    });

    expect(user.id).toBe(1);
    expect(repository.insert).toHaveBeenCalledWith({
      name: "Анна",
      email: "anna@example.com",
    });
  });
});
```

## Ошибочный случай

```ts
test("не создаёт пользователя с занятой почтой", async () => {
  const existingUser = {
    id: 1,
    name: "Анна",
    email: "anna@example.com",
  };

  const repository = {
    findByEmail: vi.fn().mockResolvedValue(existingUser),
    insert: vi.fn(),
  };

  const service = createUsersService(repository);

  await expect(
    service.create({
      name: "Другая Анна",
      email: "anna@example.com",
    }),
  ).rejects.toMatchObject({ status: 409, code: "EMAIL_EXISTS" });

  expect(repository.insert).not.toHaveBeenCalled();
});
```

## Что здесь проверяется

- прикладное правило;
- вызов репозитория;
- обработка занятой почты;
- отсутствие лишней записи при ошибке.

Настоящая уникальность дополнительно проверяется интеграционным тестом PostgreSQL.

## Что важно помнить

- Служба получает репозиторий параметром, поэтому в тесте его заменяет простой объект или `vi.fn()`.
- Проверяют результат и важные взаимодействия, например что `create` не вызван при занятой почте.
- Ошибочный сценарий так же важен, как успешный.
- Ограничения базы и SQL модульный тест не проверяет — для этого нужен интеграционный тест с PostgreSQL.

## Мини-шпаргалка

- Модульный тест службы не требует Express.
- Репозиторий заменяется управляемым объектом.
- Проверяй результат и важные взаимодействия.
- Обязательно добавляй ошибочный сценарий.
- Ограничения базы проверяются отдельно.
