# Как вызывать Express API из Vue?

> [!NOTE]
> Vue не должен знать внутреннее устройство Express или PostgreSQL. Он работает только с договором HTTP: адресом, методом, телом, кодом и JSON.

## Вопрос

Как вызывать Express API из Vue-приложения? Как обработать ошибки, `204` и состояния загрузки?

## Адрес API

```dotenv
# Vue: .env.development
VITE_API_URL=http://localhost:3000/api
```

```ts
const apiUrl = import.meta.env.VITE_API_URL;
```

В клиентские переменные `VITE_*` нельзя помещать секреты: они попадут в собранный JavaScript.

## Общая функция запроса

```ts
type ApiErrorBody = {
  error?: {
    code?: string;
    message?: string;
    details?: unknown;
  };
};

export async function apiRequest<T>(
  path: string,
  options: RequestInit = {},
): Promise<T> {
  const headers = new Headers(options.headers);

  if (options.body !== undefined && !headers.has("Content-Type")) {
    headers.set("Content-Type", "application/json");
  }

  const response = await fetch(`${apiUrl}${path}`, {
    ...options,
    credentials: "include",
    headers,
  });

  if (!response.ok) {
    const body = (await response.json().catch(() => ({}))) as ApiErrorBody;
    throw new Error(body.error?.message ?? `Ошибка HTTP ${response.status}`);
  }

  if (response.status === 204) {
    return undefined as T;
  }

  return response.json() as Promise<T>;
}
```

Заголовок `Content-Type` добавляется только к запросу с телом. Обычному `GET` он не нужен, а при обращении к другому источнику мог бы вызвать лишний предварительный запрос `OPTIONS`. Для `FormData` браузер должен сам создать заголовок с границей частей, поэтому загрузку файлов лучше оформить отдельной функцией.

## Получение пользователей

```ts
type User = {
  id: number;
  name: string;
  email: string;
};

type UsersResponse = {
  data: User[];
};

const result = await apiRequest<UsersResponse>("/users");
```

Указанный `UsersResponse` не проверяет настоящий JSON во время работы. Для особенно важной границы клиент тоже может использовать Zod или типы, созданные из OpenAPI.

## Создание

```ts
const result = await apiRequest<{ data: User }>("/users", {
  method: "POST",
  body: JSON.stringify({
    name: "Анна",
    email: "anna@example.com",
  }),
});
```

## Состояния интерфейса

Компонент должен различать:

```text
начальное состояние
загрузка
успех с данными
успех с пустым списком
ошибка проверки
ошибка авторизации
ошибка сервера или сети
```

Не показывай пользователю только сообщение `Failed to fetch`. Преобразуй известные коды API в понятные действия и тексты.

## Что важно помнить

- Адрес API задаётся через `VITE_API_URL` или относительный `/api` с прокси Vite.
- Переменные `VITE_*` попадают в бандл и видны пользователю — секретов там быть не может.
- `fetch` не бросает исключение на `404` и `500`: нужно проверить `response.ok`.
- Ответ `204` не содержит JSON — `response.json()` на нём упадёт.
- Интерфейс показывает загрузку, пустой список, ошибку и успешный результат.

## Мини-шпаргалка

- Vue работает с HTTP-договором, а не с таблицами.
- `VITE_*` доступно пользователю и не подходит для секретов.
- Проверяй `response.ok` до чтения успешных данных.
- `204` не содержит JSON.
- Интерфейс должен показывать загрузку, пустой результат и ошибку.
