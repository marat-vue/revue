# Как тестировать маршруты через Supertest и Vitest?

> [!NOTE]
> Supertest отправляет HTTP-подобный запрос прямо в Express-приложение. Настоящий порт не открывается, поэтому тест получается быстрым и удобным.

## Вопрос

Как тестировать маршруты Express через Supertest и Vitest без открытия порта?

## Установка

```bash
npm install --save-dev vitest supertest @types/supertest
```

## Почему нужен отдельный `app.ts`

```ts
// app.ts экспортирует приложение, но не вызывает listen().
export const app = express();
```

Тест импортирует `app`, а не `server.ts`.

## Проверка состояния

```ts
import request from "supertest";
import { describe, expect, test } from "vitest";
import { app } from "../src/app.js";

describe("GET /api/health", () => {
  test("возвращает состояние сервера", async () => {
    const response = await request(app).get("/api/health");

    expect(response.status).toBe(200);
    expect(response.body).toEqual({ status: "ok" });
    expect(response.headers["content-type"]).toContain("application/json");
  });
});
```

## Проверка создания

```ts
test("POST /api/users создаёт пользователя", async () => {
  const response = await request(app)
    .post("/api/users")
    .send({
      name: "Анна",
      email: `anna-${Date.now()}@example.com`,
    });

  expect(response.status).toBe(201);
  expect(response.body.data).toMatchObject({
    name: "Анна",
  });
  expect(response.body.data.id).toEqual(expect.any(Number));
});
```

## Проверка неверного тела

```ts
test("POST /api/users отклоняет неверную почту", async () => {
  const response = await request(app)
    .post("/api/users")
    .send({ name: "Анна", email: "не-почта" });

  expect(response.status).toBe(400);
  expect(response.body.error.code).toBe("VALIDATION_ERROR");
});
```

## Что проверяет такой тест

- маршрут зарегистрирован;
- JSON разбирается;
- проверка данных подключена;
- контроллер выбирает правильный код;
- общий обработчик формирует ошибку.

Если используется настоящая база, тест становится интеграционным и требует отдельного тестового окружения.

## Что важно помнить

- Supertest принимает объект `app` и сам вызывает обработчик — порт не нужен.
- Тест импортирует `app.ts`, а не `server.ts`, который вызывает `listen()`.
- Проверяют статус, важные заголовки (`Location`, `Content-Type`) и поля JSON.
- Для каждого маршрута нужен хотя бы один ошибочный запрос: неверное тело, `404`, нет прав.

## Мини-шпаргалка

- Supertest работает с объектом `app`.
- Настоящий порт для теста не нужен.
- Проверяй код, заголовок и важные поля JSON.
- Добавляй успешные и ошибочные запросы.
- Не импортируй файл, который сразу вызывает `listen()`.
