# Как настроить CORS для Vue-приложения?

> [!NOTE]
> CORS — правило браузера, которое определяет, может ли страница с одного источника читать ответ другого источника. Сервер должен явно разрешить адрес Vue-приложения.

## Вопрос

Что такое CORS и как настроить Express API для Vue-приложения на другом порту или домене?

## Основная идея

Во время разработки адреса отличаются:

```text
Vue:     http://localhost:5173
Express: http://localhost:3000
```

Порт является частью источника, поэтому браузер считает эти адреса разными.

## Установка

```bash
npm install cors
npm install --save-dev @types/cors
```

## Настройка Express

```ts
import cors from "cors";
import express from "express";
import { env } from "./config/env.js";

export const app = express();

app.use(
  cors({
    origin: env.CLIENT_ORIGIN,
    credentials: true,
  }),
);

app.use(express.json());
```

## Запрос из Vue

```ts
const response = await fetch("http://localhost:3000/api/users", {
  credentials: "include",
});
```

`credentials: "include"` нужен, если авторизация хранится в cookie.

## Нельзя сочетать любой источник и cookie

При `credentials: true` сервер не может ответить:

```text
Access-Control-Allow-Origin: *
```

Нужно вернуть конкретный разрешённый источник.

## Предварительный запрос

Перед некоторыми запросами браузер отправляет `OPTIONS`:

```text
OPTIONS /api/users
Origin: http://localhost:5173
Access-Control-Request-Method: POST
```

Пакет `cors` формирует необходимые заголовки и обрабатывает обычные предварительные запросы.

## CORS не является авторизацией

Ограничение действует в браузере. Другой сервер, Postman или `curl` могут вызвать API напрямую. Права доступа всё равно нужно проверять на сервере.

## Прокси Vite

Во время разработки можно перенаправлять `/api` через Vite:

```ts
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      "/api": "http://localhost:3000",
    },
  },
});
```

Тогда фронтенд обращается к относительному адресу `/api/users`. Но настоящий сервер всё равно должен иметь корректную настройку CORS для развёрнутого окружения, если источники различаются.

## Что важно помнить

- CORS проверяет браузер; `curl` и Postman его не применяют, поэтому там запрос «работает».
- Источник — это протокол, домен и порт вместе: `http://localhost:5173` и `http://localhost:3000` — разные источники.
- `origin: "*"` нельзя сочетать с cookie; для них нужны `credentials: true` на сервере и `credentials: "include"` в `fetch`.
- В разработке прокси Vite делает запросы same-origin и снимает вопрос CORS.
- CORS не защищает API от прямых запросов — права проверяются отдельно.

## Мини-шпаргалка

- CORS применяется браузером.
- Источник включает протокол, домен и порт.
- Разрешай конкретный адрес интерфейса.
- Для cookie нужны `credentials: true` и `credentials: "include"`.
- CORS не заменяет проверку пользователя и его прав.
