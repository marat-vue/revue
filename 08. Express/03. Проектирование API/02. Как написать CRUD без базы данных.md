# Как написать CRUD без базы данных?

> [!NOTE]
> Перед подключением PostgreSQL полезно реализовать CRUD в памяти. Так можно отдельно понять маршруты, статусы и обработку данных.

## Вопрос

Как написать CRUD API на Express с хранилищем в памяти? Какие статус-коды вернуть для каждой операции?

## Основная идея

CRUD означает четыре действия:

```text
Create → создать
Read   → прочитать
Update → изменить
Delete → удалить
```

## Временное хранилище

```ts
type User = {
  id: number;
  name: string;
  email: string;
};

const users: User[] = [
  { id: 1, name: "Анна", email: "anna@example.com" },
];

let nextId = 2;
```

После перезапуска процесса эти данные исчезнут. Это только учебный пример.

## Получение списка

```ts
app.get("/api/users", (request, response) => {
  response.json({ data: users });
});
```

## Получение одного пользователя

```ts
app.get("/api/users/:id", (request, response) => {
  const id = Number(request.params.id);
  const user = users.find((item) => item.id === id);

  if (!user) {
    response.status(404).json({
      error: { code: "USER_NOT_FOUND", message: "Пользователь не найден" },
    });
    return;
  }

  response.json({ data: user });
});
```

## Создание

```ts
app.post("/api/users", (request, response) => {
  const user: User = {
    id: nextId++,
    name: request.body.name,
    email: request.body.email,
  };

  users.push(user);

  response
    .status(201)
    .location(`/api/users/${user.id}`)
    .json({ data: user });
});
```

## Изменение

```ts
app.patch("/api/users/:id", (request, response) => {
  const id = Number(request.params.id);
  const user = users.find((item) => item.id === id);

  if (!user) {
    response.status(404).json({ message: "Пользователь не найден" });
    return;
  }

  if (request.body.name !== undefined) {
    user.name = request.body.name;
  }

  if (request.body.email !== undefined) {
    user.email = request.body.email;
  }

  response.json({ data: user });
});
```

Проверка через `!== undefined` важна: ложное значение не всегда означает отсутствие поля.

## Удаление

```ts
app.delete("/api/users/:id", (request, response) => {
  const id = Number(request.params.id);
  const index = users.findIndex((item) => item.id === id);

  if (index === -1) {
    response.status(404).json({ message: "Пользователь не найден" });
    return;
  }

  users.splice(index, 1);
  response.status(204).send();
});
```

## Чего пока не хватает

- проверки входных данных;
- проверки уникальности почты;
- постоянного хранения;
- общей обработки ошибок;
- пагинации;
- тестов.

Эти части будут добавляться последовательно.

## Что важно помнить

- CRUD в памяти помогает разобраться с маршрутами и статусами до подключения PostgreSQL.
- Данные в массиве исчезают при перезапуске и не разделяются между процессами.
- Отсутствующий ресурс возвращает `404`, успешное удаление — `204` без тела.
- Без проверки входных данных такой CRUD принимает любой JSON — этого пока не хватает.

## Мини-шпаргалка

- CRUD — создание, чтение, изменение и удаление.
- `POST` обычно возвращает `201`.
- Отсутствующий ресурс возвращает `404`.
- Удаление без тела может вернуть `204`.
- Хранилище в массиве исчезает после перезапуска.
