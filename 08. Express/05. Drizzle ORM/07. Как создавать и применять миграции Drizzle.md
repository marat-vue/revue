# Как создавать и применять миграции Drizzle?

> [!NOTE]
> Миграция — сохранённое изменение структуры базы. В командной работе схема меняется в TypeScript, Drizzle Kit создаёт SQL, разработчик проверяет его и затем применяет к базе.

## Вопрос

Как создавать и применять миграции в Drizzle? Чем `generate` и `migrate` отличаются от `push`?

## Обычный порядок

```text
Изменить schema.ts
        ↓
drizzle-kit generate
        ↓
Проверить созданный SQL
        ↓
drizzle-kit migrate
        ↓
Отправить схему и миграцию в Git
```

## Создание первой миграции

```bash
npm run db:generate -- --name=init
```

В папке `drizzle/` появятся SQL-файл и служебный снимок схемы.

## Применение

```bash
npm run db:migrate
```

Drizzle записывает сведения о выполненных миграциях в служебную таблицу и не выполняет их повторно.

## Основные команды

| Команда | Назначение |
|---|---|
| `generate` | Создать SQL из изменений TypeScript-схемы |
| `migrate` | Применить ещё не выполненные миграции |
| `push` | Сразу привести базу к схеме без файла миграции |
| `pull` | Прочитать существующую базу и создать схему |
| `studio` | Открыть просмотр данных в браузере |

## Когда использовать `push`

`push` удобен для быстрого местного прототипа:

```bash
npm run db:push
```

Для командного и рабочего окружения понятнее хранить проверяемую историю `generate + migrate`.

## Всегда читай SQL

Автоматически созданная миграция может:

- удалить столбец;
- потерять данные при смене типа;
- долго блокировать большую таблицу;
- создать обязательный столбец без значения для старых строк;
- переименовать столбец как удаление и создание.

Если добавляется обязательное поле в непустую таблицу, часто безопаснее:

1. добавить его необязательным;
2. заполнить старые строки;
3. добавить `NOT NULL` отдельной миграцией.

## Миграция и запуск приложения

Не запускай миграции одновременно в каждом экземпляре сервера без продуманной координации. Обычно их выполняет отдельный шаг развёртывания.

## Что важно помнить

- Порядок: изменить схему → `drizzle-kit generate` → прочитать SQL → `drizzle-kit migrate`.
- Файлы миграций и снимки коммитятся в Git вместе с изменением схемы.
- `push` сразу меняет базу без файла миграции — удобно для прототипа, опасно для общей и рабочей базы.
- Переименование столбца Drizzle Kit может принять за удаление и создание — сгенерированный SQL обязательно читают.
- Миграции применяют до запуска новой версии приложения, отдельным шагом деплоя.

## Мини-шпаргалка

- Схема описывает желаемое состояние.
- Миграция хранит переход между состояниями.
- `generate` создаёт SQL, `migrate` применяет его.
- `push` удобен для прототипа, но не заменяет историю изменений.
- Созданный SQL нужно прочитать до запуска.
