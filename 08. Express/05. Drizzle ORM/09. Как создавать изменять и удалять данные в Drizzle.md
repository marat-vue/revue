# Как создавать, изменять и удалять данные в Drizzle?

> [!NOTE]
> `insert`, `update` и `delete` строят соответствующий SQL. Метод `returning()` позволяет сразу получить созданные, изменённые или удалённые строки PostgreSQL.

## Вопрос

Как создавать, изменять и удалять данные в Drizzle? Как получить результат операции и обработать конфликт уникальности?

## Создание

```ts
const [createdUser] = await db
  .insert(users)
  .values({
    name: input.name,
    email: input.email,
  })
  .returning();
```

`createdUser` содержит и значения, заданные базой: идентификатор и даты.

## Несколько строк

```ts
await db.insert(users).values([
  { name: "Анна", email: "anna@example.com" },
  { name: "Илья", email: "ilya@example.com" },
]);
```

## Конфликт уникальности

```ts
const [createdUser] = await db
  .insert(users)
  .values(input)
  .onConflictDoNothing({ target: users.email })
  .returning();
```

Если почта занята, массив будет пустым. Для обычного API также можно позволить PostgreSQL вернуть ошибку `23505` и преобразовать её в `409`.

## Частичное изменение

```ts
const [updatedUser] = await db
  .update(users)
  .set({
    ...input,
    updatedAt: new Date(),
  })
  .where(eq(users.id, id))
  .returning();
```

Если строка не найдена, `updatedUser` равен `undefined`.

## Удаление

```ts
const [deletedUser] = await db
  .delete(users)
  .where(eq(users.id, id))
  .returning({ id: users.id });
```

## Опасность запроса без `where`

```ts
// Изменит все строки.
await db.update(users).set({ isBlocked: true });

// Удалит все строки.
await db.delete(users);
```

Drizzle делает запрос явным, но не угадывает намерение разработчика. Включай строгие проверки Drizzle Kit и внимательно просматривай код изменения данных.

## Проверка входа остаётся обязательной

```ts
const input = updateUserSchema.parse(request.body);
```

Не передавай `request.body` прямо в `.set()`: клиент может попытаться изменить `id`, роль или другое запрещённое поле.

## Что важно помнить

- `.returning()` возвращает строки, которые реально изменил PostgreSQL.
- `onConflictDoNothing()` и `onConflictDoUpdate()` решают конфликт уникальности на стороне базы.
- `update` и `delete` без `.where()` затрагивают всю таблицу.
- В `.set()` передаются только проверенные поля, а не весь `request.body`.

## Мини-шпаргалка

- `.insert().values()` создаёт строки.
- `.update().set().where()` изменяет выбранные строки.
- `.delete().where()` удаляет выбранные строки.
- `.returning()` возвращает результат PostgreSQL.
- Никогда не передавай необработанный `request.body` в запрос.
