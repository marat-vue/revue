# Как выполнять транзакции и сырой SQL в Drizzle?

> [!NOTE]
> Drizzle предоставляет удобный `db.transaction()`. Внутри обратной функции используй объект `tx`, чтобы все запросы выполнялись в одной транзакции.

## Вопрос

Как выполнять транзакции в Drizzle и когда использовать сырой SQL через шаблон `sql`?

## Транзакция

```ts
await db.transaction(async (tx) => {
  const [user] = await tx
    .insert(users)
    .values({
      name: input.name,
      email: input.email,
    })
    .returning({ id: users.id });

  if (!user) {
    throw new Error("Пользователь не создан");
  }

  await tx.insert(tasks).values({
    userId: user.id,
    title: "Первая задача",
  });
});
```

Если код выбросит ошибку, Drizzle откатит транзакцию. Если завершится успешно — подтвердит.

## Частая ошибка

```ts
await db.transaction(async (tx) => {
  await tx.insert(users).values(input);

  // Плохо: запрос идёт через db, а не через tx.
  await db.insert(tasks).values(task);
});
```

Второй запрос не входит в текущую транзакцию.

## SQL-фрагмент

```ts
import { sql } from "drizzle-orm";

const result = await db
  .select()
  .from(users)
  .where(sql`lower(${users.email}) = ${email.toLowerCase()}`);
```

Значение `email` превращается в безопасный параметр, а ссылка `users.email` — в корректное имя столбца.

## Вычисляемое поле

```ts
const result = await db
  .select({
    id: users.id,
    normalizedName: sql<string>`lower(${users.name})`,
  })
  .from(users);
```

Указание `<string>` сообщает TypeScript ожидаемый тип, но не проверяет значение во время работы.

## Полностью сырой запрос

```ts
const result = await db.execute(sql`
  SELECT current_database() AS database, now() AS time
`);
```

## Когда нужен сырой SQL

- особая функция PostgreSQL;
- сложный общий табличный запрос;
- возможность, которой ещё нет в построителе;
- точная оптимизация;
- диагностический запрос.

Не вставляй пользовательскую строку через `sql.raw()`. Обычная подстановка `${value}` безопасно создаёт параметр.

## Что важно помнить

- Внутри `db.transaction(async (tx) => ...)` все запросы выполняются через `tx`, а не через `db`.
- Исключение внутри колбэка откатывает транзакцию; `tx.rollback()` откатывает её явно.
- Значения в шаблоне `sql` подставляются как параметры и защищены от инъекций.
- `sql.raw()` вставляет строку как есть — только для заранее известных фрагментов, не для данных пользователя.

## Мини-шпаргалка

- `db.transaction()` объединяет запросы.
- Внутри транзакции используй только `tx`.
- Ошибка откатывает транзакцию.
- Шаблон `sql` позволяет добавить возможности PostgreSQL.
- Пользовательские значения передаются через безопасную подстановку.
