# Какие типы, ограничения и значения по умолчанию есть в Drizzle?

> [!NOTE]
> Тип столбца задаёт форму данных, а ограничения защищают их целостность внутри PostgreSQL. Важные правила должны существовать в базе, даже если приложение уже проверяет вход через Zod.

## Вопрос

Какие типы столбцов, ограничения и значения по умолчанию есть в Drizzle для PostgreSQL?

## Частые типы PostgreSQL

```ts
import {
  boolean,
  integer,
  jsonb,
  numeric,
  pgEnum,
  pgTable,
  text,
  timestamp,
  uuid,
  varchar,
} from "drizzle-orm/pg-core";
```

| Drizzle | PostgreSQL | Пример |
|---|---|---|
| `integer()` | `integer` | счётчик, внешний ключ |
| `text()` | `text` | длинный текст |
| `varchar({ length })` | `varchar(n)` | почта, короткое имя |
| `boolean()` | `boolean` | признак |
| `timestamp()` | `timestamp` | дата и время |
| `uuid()` | `uuid` | случайный идентификатор |
| `numeric()` | `numeric` | точная денежная величина |
| `jsonb()` | `jsonb` | гибкая структура JSON |

## Обязательность

```ts
name: varchar("name", { length: 100 }).notNull(),
```

Без `.notNull()` поле допускает `null`, и это отразится в типе TypeScript.

## Значение по умолчанию

```ts
isActive: boolean("is_active").notNull().default(true),
createdAt: timestamp("created_at", { withTimezone: true })
  .notNull()
  .defaultNow(),
```

По умолчанию значение задаёт сама база. Оно применяется независимо от того, какое приложение выполняет вставку.

## Уникальность

```ts
email: varchar("email", { length: 255 }).notNull().unique(),
```

Проверка `SELECT` перед `INSERT` не гарантирует уникальность при одновременных запросах. Ограничение `UNIQUE` гарантирует.

## Перечисление

```ts
export const taskStatus = pgEnum("task_status", [
  "new",
  "in_progress",
  "done",
]);

export const tasks = pgTable("tasks", {
  id: integer("id").primaryKey().generatedAlwaysAsIdentity(),
  status: taskStatus("status").notNull().default("new"),
});
```

Изменение перечисления в PostgreSQL требует аккуратной миграции. Для часто меняющихся значений иногда проще отдельная таблица или текст с проверкой.

## Деньги

Для денег не используй `real` или `double precision`. Выбери:

- целое число минимальных единиц, например копеек;
- `numeric` с явно продуманным преобразованием строки.

## Что важно помнить

- Столбец без `.notNull()` допускает `NULL`, и тип поля в TypeScript включает `null`.
- `.default()` и `.defaultNow()` выполняются в базе, а `.$defaultFn()` — в приложении.
- Уникальность проверяется ограничением базы: проверка `SELECT` перед `INSERT` не спасает от гонки.
- Для моментов времени используют `timestamp` с `withTimezone: true` (`timestamptz`).
- Деньги хранят в `numeric` или в целых копейках, но не в `real` / `double precision`.

## Мини-шпаргалка

- `.notNull()` запрещает `NULL`.
- `.default()` и `.defaultNow()` задают значение в базе.
- `.unique()` защищает от дубликатов при одновременных запросах.
- `timestamptz` подходит для моментов времени.
- Денежные значения требуют точного типа.
