# Что такое Vite и как он работает

> [!NOTE]
> **Vite** — инструмент сборки и dev-сервер, созданный автором Vue Эваном Ю; стандарт для новых Vue-проектов (`npm create vue@latest`) и основа Nuxt. В режиме разработки Vite **не бандлит код приложения**: браузер запрашивает нативные ES-модули, а Vite трансформирует каждый файл по запросу (`.vue`, TS, CSS) — поэтому старт почти мгновенный независимо от размера проекта. Зависимости из `node_modules` один раз **предварительно бандлятся** через esbuild. Для production Vite делает полноценную оптимизированную сборку через Rollup (в новых версиях — Rolldown).

## Вопрос

Что такое Vite и почему он быстрее webpack в разработке? Как устроены dev-режим и production-сборка?

## Создание проекта

```bash
npm create vue@latest my-app
# или минимальный шаблон без роутера и Pinia:
npm create vite@latest my-app -- --template vue-ts
```

```text
my-app/
  index.html          ← точка входа — HTML, а не JS
  src/main.ts
  src/App.vue
  vite.config.ts      ← plugins: [vue()]
  public/             ← файлы копируются как есть
```

```html
<!-- index.html -->
<div id="app"></div>
<script type="module" src="/src/main.ts"></script>
```

## Dev-режим

```text
Браузер: GET /src/main.ts
  → Vite: esbuild/oxc трансформирует TS → JS (без проверки типов)
  → ответ: import { createApp } from "/node_modules/.vite/deps/vue.js"
Браузер: GET /src/App.vue
  → @vitejs/plugin-vue: @vue/compiler-sfc компилирует <template> в render-функцию,
    <script setup> — в JS, <style> — в отдельный CSS-модуль (?vue&type=style)
```

- **pre-bundling зависимостей**: CommonJS-пакеты превращаются в ESM, сотни файлов `lodash-es` — в один, результат кешируется в `node_modules/.vite`;
- **трансформация по запросу**: обрабатываются только файлы, которые реально открыл браузер;
- **HMR** через WebSocket: при изменении `.vue`-файла заменяется только этот компонент, состояние сохраняется. Если изменился только `<template>`, Vue перерендерит компонент без пересоздания `setup`; если `<style>` — заменятся только стили.

## Production-сборка

```bash
npm run build      # vite build → dist/
npm run preview    # локальный сервер для проверки dist
```

- полный бандлинг через Rollup: tree shaking, разбиение на чанки, минификация (esbuild), хеши в именах;
- CSS извлекается в файлы, для ленивых чанков подключается автоматически;
- `<link rel="modulepreload">` для нужных сразу чанков.

## Почему Vite быстрый

| | webpack (классический) | Vite |
| --- | --- | --- |
| Старт dev-сервера | бандлит всё приложение | почти сразу, без бандлинга |
| Изменение файла | пересборка затронутых чанков | трансформация одного модуля |
| Транспиляция | vue-loader + Babel/ts-loader (JS) | plugin-vue + esbuild/oxc (нативный код) |
| Конфигурация | много loaders и plugins | разумные значения по умолчанию |

## Что Vite не делает

- **не проверяет типы** TypeScript — для `.vue`-файлов нужен `vue-tsc --noEmit` (обычный `tsc` не понимает SFC) в скрипте или плагин `vite-plugin-checker`;
- не заменяет фреймворк: роутинг берут из Vue Router, состояние — из Pinia, а SSR — из Nuxt (он построен на Vite) или `vite-ssr`-настройки вручную.

## Что важно помнить

- Различие dev (ESM без бандла) и prod (Rollup-бандл) иногда дает разное поведение — проверяйте `vite preview` перед релизом.
- В dev на холодном старте может быть много запросов модулей — это нормально, они кешируются.
- Плагины Vite совместимы с экосистемой Rollup.
- Vitest использует ту же конфигурацию и трансформации, что и Vite, поэтому `.vue`-файлы в тестах компилируются тем же плагином.
- Vue CLI (на webpack) находится в режиме поддержки — новые проекты создают на Vite, старые мигрируют.

## Мини-шпаргалка

Vite: dev — нативный ESM, трансформация по запросу, pre-bundling зависимостей esbuild, HMR компонентов через plugin-vue. Prod — Rollup/Rolldown: tree shaking, чанки, минификация, хеши. Типы не проверяет — `vue-tsc --noEmit`. Точка входа — `index.html`.
