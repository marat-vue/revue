# Как работает HMR

> [!NOTE]
> **HMR (Hot Module Replacement)** — замена измененного модуля в работающем приложении без полной перезагрузки страницы. Dev-сервер следит за файлами, по **WebSocket** сообщает браузеру, какой модуль изменился, браузер загружает новую версию, а модуль или его родитель **принимает** обновление (`import.meta.hot.accept`). Во Vue это делает `@vitejs/plugin-vue` (в webpack — `vue-loader`) вместе с runtime HMR Vue: компонент перерисовывается с сохранением состояния (`ref` в `setup`, `data`), а при изменении не-компонентного модуля обновление поднимается выше — до границы HMR или полной перезагрузки.

## Вопрос

Как работает HMR? Чем он отличается от live reload и почему иногда состояние Vue-компонента сбрасывается после изменения файла?

## Live reload и HMR

| | Live reload | HMR |
| --- | --- | --- |
| Что происходит | полная перезагрузка страницы | замена одного модуля |
| Состояние приложения | теряется | обычно сохраняется |
| Скорость | секунды | миллисекунды |

## Механизм

```text
1. Вы сохранили BaseButton.vue
2. Dev-сервер (Vite/webpack) видит изменение, трансформирует файл
3. По WebSocket: { type: "update", path: "/src/BaseButton.vue", timestamp }
4. Браузер: import("/src/BaseButton.vue?t=1729...")   — новая версия модуля
5. Ищется граница HMR — модуль, который «принимает» обновление
6. Vue HMR runtime (__VUE_HMR_RUNTIME__) подменяет render или весь компонент у живых экземпляров
7. Если границы нет — обновление поднимается к корню → полная перезагрузка
```

## HMR API (Vite)

```typescript
// обычно пишут плагины, а не прикладной код
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // применить новую версию модуля
  });
  import.meta.hot.dispose(() => {
    clearInterval(timerId);          // очистить побочные эффекты старой версии
  });
}
```

В webpack — `module.hot.accept()`.

## Как HMR работает во Vue SFC

`@vitejs/plugin-vue` сравнивает блоки `.vue`-файла до и после изменения:

| Что изменилось | Что происходит | Состояние |
| --- | --- | --- |
| только `<template>` | `rerender`: подменяется render-функция, `setup` не вызывается заново | сохраняется |
| только `<style>` (в том числе scoped) | заменяется CSS-модуль, компонент не трогается | сохраняется |
| `<script>` / `<script setup>` | `reload`: экземпляры пересоздаются, `setup` выполняется заново | локальное сбрасывается |
| обычный `.ts`-модуль (composable, утилита) | обновление поднимается к импортерам до границы HMR | сбрасывается у затронутых компонентов, иногда — полная перезагрузка |

Состояние в **Pinia** переживает HMR компонентов, потому что живет вне них. Чтобы при правке самого store не терять данные, в файле store добавляют `acceptHMRUpdate`:

```typescript
import { defineStore, acceptHMRUpdate } from "pinia";

export const useCartStore = defineStore("cart", { /* ... */ });

if (import.meta.hot) {
  import.meta.hot.accept(acceptHMRUpdate(useCartStore, import.meta.hot));
}
```

## Типичные проблемы

| Проблема | Причина | Решение |
| --- | --- | --- |
| HMR не работает в Docker/WSL | файловые события не доходят | `server.watch.usePolling: true` |
| Постоянная полная перезагрузка | изменился модуль без границы HMR (например, `main.ts` или `router.ts`) | вынести часто меняемый код в компоненты и store |
| Дублируются слушатели и таймеры | побочные эффекты на уровне модуля | `import.meta.hot.dispose`, эффекты в компонентах |
| WebSocket не подключается за прокси | прокси не пропускает upgrade | `server.hmr.clientPort`, настройка прокси |

## Что важно помнить

- HMR существует только в режиме разработки.
- При изменении только `<template>` или `<style>` состояние компонента сохраняется; изменение `<script setup>` пересоздает компонент.
- Глобальные side effects в модулях (подписки, интервалы) при HMR дублируются — держите их в `onMounted` / `onUnmounted` или composables с очисткой.
- В Nuxt HMR работает так же, плюс серверный код (`server/`) перезапускается через Nitro.

## Мини-шпаргалка

HMR: сервер следит за файлами → WebSocket → браузер грузит новую версию модуля → граница `hot.accept` применяет → иначе полная перезагрузка. Vue SFC: `<template>` → rerender с сохранением состояния, `<style>` → замена CSS, `<script>` → reload компонента. Pinia — `acceptHMRUpdate`. `dispose` для очистки.
