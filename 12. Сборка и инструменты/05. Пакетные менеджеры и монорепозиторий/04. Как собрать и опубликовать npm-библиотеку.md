# Как собрать и опубликовать npm-библиотеку

> [!NOTE]
> Библиотеку собирают иначе, чем приложение: нужен не один бандл для браузера, а **модули для других сборщиков** — ESM (и при необходимости CommonJS), **типы `.d.ts`**, корректное поле **`exports`** в `package.json`, внешние (`external`) зависимости вместо встроенных копий, `peerDependencies` для Vue и пометка **`sideEffects`** для tree shaking. Библиотеку Vue-компонентов (`.vue`-файлы) собирают через **Vite в library mode** с `@vitejs/plugin-vue` и `vite-plugin-dts`; утилиты и composables без `.vue` — через **tsup** или **tsdown**, публикацию — через `npm publish` с provenance из CI.

## Вопрос

Как собрать и опубликовать npm-библиотеку компонентов или утилит? Какие поля `package.json` важны и почему Vue должен быть `peerDependency`?

## package.json библиотеки

```json
{
  "name": "@acme/ui",
  "version": "1.2.0",
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "sideEffects": ["*.css"],
  "peerDependencies": { "vue": "^3.4.0" },
  "devDependencies": { "vue": "^3.5.0", "vite": "^7.0.0", "@vitejs/plugin-vue": "^6.0.0", "vite-plugin-dts": "^4.0.0", "vue-tsc": "^3.0.0", "typescript": "^5.9.0" },
  "scripts": { "build": "vite build", "prepublishOnly": "npm run build" }
}
```

| Поле | Зачем |
| --- | --- |
| `exports` | публичные точки входа и условия `types` / `import` / `require`; `types` — первым |
| `files` | что попадет в пакет (без исходников тестов и конфигов) |
| `sideEffects` | разрешает tree shaking; CSS-импорты помечаются как побочные эффекты |
| `peerDependencies` | Vue ставит приложение — нет второй копии, `provide`/`inject` и плагины работают |
| `main` / `module` / `types` | для старых инструментов без поддержки `exports` |

## Сборка через Vite library mode

```typescript
// vite.config.ts
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";
import dts from "vite-plugin-dts";

export default defineConfig({
  plugins: [vue(), dts({ tsconfigPath: "./tsconfig.app.json" })], // .d.ts через vue-tsc
  build: {
    lib: {
      entry: "src/index.ts",
      formats: ["es", "cjs"],
      fileName: (format) => (format === "es" ? "index.js" : "index.cjs"),
    },
    sourcemap: true,
    cssFileName: "styles",                 // стили компонентов → dist/styles.css
    rollupOptions: {
      external: ["vue"],                   // Vue не встраивается в библиотеку
      output: { globals: { vue: "Vue" } },
    },
  },
});
```

```typescript
// src/index.ts
export { default as AcmeButton } from "./components/AcmeButton.vue";
export { default as AcmeModal } from "./components/AcmeModal.vue";
export { useToast } from "./composables/useToast";

// опционально — плагин для глобальной регистрации
import type { App } from "vue";
import AcmeButton from "./components/AcmeButton.vue";
export default { install(app: App) { app.component("AcmeButton", AcmeButton); } };
```

Для пакета только с TS-кодом (composables, утилиты) проще tsup: `entry`, `format: ["esm"]`, `dts: true`, `external: ["vue"]`.

Для нового пакета, который нужен только современным потребителям, достаточно одного формата ESM — так проще и нет dual package hazard.

## Проверка перед публикацией

```bash
npm pack --dry-run                   # какие файлы попадут в пакет
npx publint                          # ошибки в package.json и exports
npx @arethetypeswrong/cli --pack .   # корректность типов для разных резолверов
```

## Публикация

```bash
npm login
npm version minor                    # 1.2.0 → 1.3.0 + git tag
npm publish --access public          # для scoped-пакетов
```

Из CI (GitHub Actions) с provenance — подтверждением, что пакет собран из конкретного коммита:

```yaml
- run: npm publish --provenance --access public
  env:
    NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

В монорепозитории версии и changelog удобно вести через Changesets.

## Что важно помнить

- Библиотека не должна встраивать Vue, а также крупные зависимости, которые есть у потребителя, — указывайте их в `external`/`peerDependencies`.
- Компоненты должны корректно работать при SSR (Nuxt): не обращайтесь к `window` и `document` в `setup` — только в `onMounted`. Для Nuxt можно дополнительно выпустить модуль, который регистрирует компоненты с авто-импортом.
- Не публикуйте `src` и тесты — используйте `files`.
- Ломающие изменения — только в major-версии с описанием миграции.

## Мини-шпаргалка

Библиотека: ESM (+CJS при необходимости), `.d.ts`, `exports` с `types` первым, `files`, `sideEffects`, Vue в `peerDependencies` и `external`. Сборка: Vite library mode + plugin-vue + vite-plugin-dts (компоненты), tsup/tsdown (утилиты). Проверка: `npm pack --dry-run`, publint, arethetypeswrong. Публикация: `npm version`, `npm publish --provenance` из CI.
