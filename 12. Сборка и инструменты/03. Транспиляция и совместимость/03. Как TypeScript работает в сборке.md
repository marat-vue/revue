# Как TypeScript работает в сборке

> [!NOTE]
> В современных сборках TypeScript обрабатывается **двумя независимыми шагами**: быстрый транспилятор (esbuild, SWC, oxc, Babel) **удаляет типы** файл за файлом и не проверяет их, а **`vue-tsc --noEmit`** (обертка над `tsc`, которая понимает `.vue`-файлы) отдельно **проверяет типы** во всем проекте — в редакторе, в pre-commit или в CI. Поскольку транспилятор видит только один файл, в `tsconfig` включают `isolatedModules` (или `verbatimModuleSyntax`), чтобы запретить конструкции, требующие знаний о других файлах. `tsc` с генерацией файлов используют в основном для библиотек — ради `.d.ts`.

## Вопрос

Как TypeScript обрабатывается при сборке фронтенд-проекта? Почему Vite не показывает ошибки типов и зачем нужны `isolatedModules` и `vue-tsc`?

## Два шага

```text
src/*.ts, src/*.vue
  ├─▶ plugin-vue + esbuild / oxc: удалить типы → JS → бандл   (быстро, без проверки)
  └─▶ vue-tsc --noEmit: проверить типы, включая шаблоны         (медленнее, отдельно)
```

```json
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "run-p type-check \"build-only {@}\" --",
    "build-only": "vite build",
    "type-check": "vue-tsc --build"
  }
}
```

Так устроен шаблон `npm create vue@latest`: проверка типов и сборка идут параллельно (`run-p` из `npm-run-all2`). Если в коде ошибка типа, `vite dev` всё равно запустится — ошибку покажет редактор (расширение Vue - Official / Volar), `npm run type-check` или CI.

`vue-tsc` проверяет и шаблоны: опечатку в имени prop, неверный тип события в `@click`, несуществующую переменную в `{{ }}`. Обычный `tsc` `.vue`-файлы пропускает.

## Важные опции tsconfig для сборки

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",       // разрешение импортов как у бандлера
    "jsx": "preserve",                   // JSX во Vue (если используется) обрабатывает plugin-vue-jsx
    "strict": true,
    "noEmit": true,                       // файлы генерирует бандлер
    "isolatedModules": true,              // каждый файл транспилируется отдельно
    "verbatimModuleSyntax": true,         // import type сохраняется как написано
    "skipLibCheck": true,
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src/**/*.ts", "src/**/*.vue", "env.d.ts"]
}
```

## Почему isolatedModules

Транспилятор обрабатывает файл без информации о других:

```typescript
// re-export типа: транспилятор не знает, тип это или значение
export { User } from "./types";          // ошибка с isolatedModules
export type { User } from "./types";     // правильно

// const enum требует знать значения из другого файла
const enum Direction { Up, Down }        // избегайте; используйте объект as const
```

## Проектные ссылки и скорость

- `tsc --build` с `references` проверяет монорепозиторий по частям с кешем (`tsBuildInfoFile`);
- `skipLibCheck` пропускает проверку `.d.ts` библиотек;
- в шаблоне create-vue несколько tsconfig: `tsconfig.app.json` (код приложения), `tsconfig.node.json` (конфиги Vite и инструментов), `tsconfig.vitest.json` (тесты) и корневой `tsconfig.json` с `references` — поэтому `vue-tsc --build`.

## TypeScript для библиотек

```bash
tsc --emitDeclarationOnly --declaration --outDir dist   # только .d.ts
```

Для библиотеки Vue-компонентов `.d.ts` генерирует `vue-tsc --declaration --emitDeclarationOnly` или Vite library mode + `vite-plugin-dts` (использует vue-tsc внутри). Для чистого TS — tsup, tsdown.

## Что важно помнить

- Транспилятор ≠ проверка типов: сборка может пройти с ошибками типов, если не запускать `vue-tsc`.
- Проверку типов обязательно включайте в CI.
- `moduleResolution: "Bundler"` — для проектов на Vite/webpack, `"NodeNext"` — для кода, который запускает Node.js напрямую.
- `paths` в tsconfig не меняет импорты в собранном коде — алиасы должен понимать и бандлер.
- Связанные темы: [Babel и SWC](<01. Что такое Babel и SWC.md>), [TypeScript в Node.js без сборки](<../../08. Node/16. Современные API диагностика и security/07. Как Node.js запускает TypeScript без сборки и какие ограничения.md>).

## Мини-шпаргалка

Сборка TS во Vue = транспиляция без проверки (plugin-vue + esbuild/oxc) + `vue-tsc --noEmit` / `--build` отдельно (редактор, CI). tsconfig: `noEmit`, `isolatedModules`, `verbatimModuleSyntax`, `moduleResolution: "Bundler"`, `strict`, `paths`. `export type` для типов, без `const enum`. Библиотеки — `.d.ts` через vue-tsc / vite-plugin-dts.
