# Что такое Babel и SWC

> [!NOTE]
> **Транспилятор** переводит код с одного варианта JavaScript на другой: TypeScript — в обычный JS, современный синтаксис (`?.`, `??`, классовые поля) — в более старый для целевых браузеров. **Babel** — исторический стандарт на JavaScript с огромной экосистемой плагинов. **SWC** — аналог на Rust, в 20–70 раз быстрее; его используют Rspack, Jest (через `@swc/jest`) и многие инструменты. Во Vue-проекте до транспилятора работает ещё один шаг — **компилятор SFC** (`@vue/compiler-sfc`), который превращает `.vue`-файл в JS и CSS. Транспилятор меняет **синтаксис**, но не добавляет отсутствующие **API** — для этого нужны полифилы.

## Вопрос

Что такое Babel и SWC и зачем они нужны? Чем транспиляция отличается от полифилов и компиляции шаблонов Vue? Чем SWC отличается от Babel?

## Что делает транспилятор

```typescript
// до
const name = user?.profile?.name ?? "Гость";
```

```javascript
// после (для старых браузеров, упрощенно)
var _user$profile$name, _user$profile;
var name =
  (_user$profile$name =
    user === null || user === void 0
      ? void 0
      : (_user$profile = user.profile) === null || _user$profile === void 0
        ? void 0
        : _user$profile.name) !== null && _user$profile$name !== void 0
    ? _user$profile$name
    : "Гость";
```

Типичные задачи:

- удаление типов TypeScript;
- понижение синтаксиса под `browserslist`;
- JSX → вызовы `h()` для Vue-компонентов на JSX (`@vue/babel-plugin-jsx`);
- плагины: удаление `console`, макросы, инструментирование для покрытия.

## Как собирается .vue-файл

```vue
<!-- Greeting.vue -->
<script setup lang="ts">
const props = defineProps<{ name: string }>();
</script>

<template>
  <h1>Привет, {{ props.name }}</h1>
</template>
```

```text
Greeting.vue
  → @vue/compiler-sfc: разбор на блоки
      <script setup lang="ts"> → компиляция макросов (defineProps) → TS
      <template>               → render-функция с patch flags и hoisting
      <style scoped>           → CSS с атрибутом data-v-xxxx
  → esbuild / oxc / SWC / Babel: TS → JS, понижение синтаксиса
  → бандл
```

```javascript
// упрощенный результат компиляции шаблона
import { toDisplayString as _toDisplayString, openBlock as _openBlock, createElementBlock as _createElementBlock } from "vue";

function render(_ctx) {
  return (_openBlock(), _createElementBlock("h1", null, "Привет, " + _toDisplayString(_ctx.props.name), 1 /* TEXT */));
}
```

Компилятор SFC вызывается плагином бандлера: `@vitejs/plugin-vue` в Vite, `vue-loader` в webpack. Транспилятор после него видит уже обычный TS/JS. Флаг `1 /* TEXT */` — patch flag: при обновлении Vue сравнит только текст, а не весь элемент.

## Конфигурация Babel

Во Vue + Vite Babel обычно не нужен: TS снимает esbuild/oxc, а синтаксис понижает `build.target` или `@vitejs/plugin-legacy`. Babel встречается в проектах на Vue CLI и в Jest:

```javascript
// babel.config.js (Vue CLI)
module.exports = {
  presets: ["@vue/cli-plugin-babel/preset"], // preset-env + JSX для Vue + polyfills по usage
};
```

```json
// babel.config.json (вручную)
{
  "presets": [
    ["@babel/preset-env", { "useBuiltIns": "usage", "corejs": "3.40" }],
    "@babel/preset-typescript"
  ],
  "plugins": ["@vue/babel-plugin-jsx"]
}
```

- **preset** — набор плагинов (`preset-env` выбирает нужные трансформации по целевым браузерам);
- **plugin** — одна трансформация;
- **AST**: Babel парсит код в дерево, плагины меняют дерево, затем код генерируется обратно.

## SWC

```json
// .swcrc
{
  "jsc": {
    "parser": { "syntax": "typescript" },
    "target": "es2020"
  }
}
```

Где SWC уже внутри: Rspack (`builtin:swc-loader`, в том числе для Vue-проектов на Rspack), Deno, Parcel, `unplugin-swc` для Vite и Vitest (когда нужны декораторы с метаданными).

## Babel и SWC

| | Babel | SWC |
| --- | --- | --- |
| Язык | JavaScript | Rust |
| Скорость | базовая | в десятки раз быстрее |
| Плагины | огромная экосистема | меньше, плагины на Rust/WASM |
| Где используется | Vue CLI, Jest (`babel-jest`), особые плагины | Rspack, новые проекты |

Также есть **esbuild** (Go) и **oxc** (Rust) — Vite использует их для трансформации TS после компиляции SFC.

## Транспиляция и полифилы

| | Транспиляция | Полифил |
| --- | --- | --- |
| Что решает | новый **синтаксис** (`?.`, `class #private`, `async`) | отсутствующие **API** (`Array.prototype.at`, `Promise.withResolvers`, `structuredClone`) |
| Как | переписывает код при сборке | добавляет реализацию в рантайме |
| Инструмент | Babel, SWC, esbuild | core-js, отдельные полифилы |

## Что важно помнить

- Транспилятор не проверяет типы TypeScript — только удаляет их; проверка для Vue — `vue-tsc --noEmit`.
- Компилятор шаблонов Vue и транспилятор — разные шаги: первый превращает `<template>` в render-функцию, второй работает с готовым JS/TS.
- Чем современнее целевые браузеры, тем меньше трансформаций и меньше бандл.
- Транспиляция `node_modules` обычно отключена для скорости — если библиотека поставляет новый синтаксис, а нужны старые браузеры, ее включают явно (`transpileDependencies` в Vue CLI).

Оптимизация и производительность/03. Как Vue оптимизирует Virtual DOM - компилятор, block tree и patch flags.md>).

## Мини-шпаргалка

`.vue` → `@vue/compiler-sfc` (template → render, script setup → JS/TS, scoped style) → транспилятор (TS → JS, новый синтаксис → старый). Babel — JS, плагины и presets (`preset-env`, `preset-typescript`, `@vue/babel-plugin-jsx`). SWC — Rust, быстрый, в Rspack. Синтаксис — транспиляция, API — полифилы (core-js). Типы не проверяет.
