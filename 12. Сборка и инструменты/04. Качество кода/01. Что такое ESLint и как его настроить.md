# Что такое ESLint и как его настроить

> [!NOTE]
> **ESLint** — статический анализатор JavaScript и TypeScript: он находит ошибки и опасные паттерны **до запуска кода** (неиспользуемые переменные, мутация props, `v-for` без `key`, `v-if` вместе с `v-for`, забытый `await`, проблемы доступности). Для `.vue`-файлов нужен **`eslint-plugin-vue`** — он разбирает `<template>` и `<script>` через `vue-eslint-parser`. Правила подключаются из плагинов (`typescript-eslint`, `eslint-plugin-vue`, `eslint-plugin-vuejs-accessibility`, `import`), многие исправляются автоматически (`--fix`). С ESLint 9 по умолчанию используется **flat config** — файл `eslint.config.js` (или `.ts`) с массивом объектов конфигурации. Форматирование (отступы, кавычки) обычно отдают Prettier.

## Вопрос

Что такое ESLint и зачем он нужен? Как настроить ESLint для Vue и TypeScript в формате flat config и как он сочетается с Prettier?

## Flat config для Vue + TypeScript

Шаблон `npm create vue@latest` генерирует конфиг через пакет `@vue/eslint-config-typescript`, который связывает `eslint-plugin-vue` и `typescript-eslint` для `.vue`-файлов:

```typescript
// eslint.config.ts
import { globalIgnores } from "eslint/config";
import { defineConfigWithVueTs, vueTsConfigs } from "@vue/eslint-config-typescript";
import pluginVue from "eslint-plugin-vue";
import pluginVueA11y from "eslint-plugin-vuejs-accessibility";
import pluginVitest from "@vitest/eslint-plugin";
import skipFormatting from "@vue/eslint-config-prettier/skip-formatting";

export default defineConfigWithVueTs(
  { name: "app/files-to-lint", files: ["**/*.{ts,mts,tsx,vue}"] },
  globalIgnores(["**/dist/**", "**/coverage/**"]),

  pluginVue.configs["flat/recommended"],          // правила шаблонов и SFC
  ...pluginVueA11y.configs["flat/recommended"],    // доступность в шаблонах
  vueTsConfigs.recommendedTypeChecked,             // typescript-eslint с поддержкой .vue

  {
    rules: {
      "vue/multi-word-component-names": "error",
      "vue/no-unused-properties": "warn",
      "vue/block-lang": ["error", { script: { lang: "ts" } }],
      "vue/define-macros-order": ["warn", { order: ["defineProps", "defineEmits", "defineModel"] }],
      "@typescript-eslint/no-floating-promises": "error",
      "@typescript-eslint/no-unused-vars": ["error", { argsIgnorePattern: "^_" }],
      "no-console": ["warn", { allow: ["warn", "error"] }],
    },
  },

  { ...pluginVitest.configs.recommended, files: ["src/**/__tests__/*", "src/**/*.test.ts"] },
  skipFormatting,                                  // отключает правила, конфликтующие с Prettier — последним
);
```

```json
// package.json
{ "scripts": { "lint": "eslint . --fix --cache" } }
```

## Как устроен flat config

| Часть | Назначение |
| --- | --- |
| массив объектов | применяются по порядку, последующие переопределяют предыдущие |
| `files` / `ignores` | к каким файлам относится объект |
| `languageOptions` | парсер (`vue-eslint-parser` для `.vue`), глобальные переменные, версия ECMAScript |
| `plugins` | объекты плагинов, подключенные напрямую через import |
| `rules` | `"off"` / `"warn"` / `"error"` + настройки |

Старый формат `.eslintrc` с `extends: ["plugin:vue/vue3-recommended"]` строками и `env` устарел. Хелпер `defineConfigWithVueTs` нужен, потому что typescript-eslint должен знать, что `<script lang="ts">` внутри `.vue` — это TypeScript.

## Уровни правил eslint-plugin-vue

| Конфиг | Что включает |
| --- | --- |
| `flat/essential` | ошибки: `v-for` без `key`, мутация props, неверные директивы, дублирующиеся ключи |
| `flat/strongly-recommended` | + читаемость: порядок атрибутов в одну строку, самозакрывающиеся теги, регистр имен |
| `flat/recommended` | + единообразие: порядок блоков SFC и опций компонента |

## Полезные правила и плагины

| Плагин / правило | Что ловит |
| --- | --- |
| `vue/no-mutating-props` | `props.items.push(...)` — изменение props в дочернем компоненте |
| `vue/require-v-for-key`, `vue/no-use-v-if-with-v-for` | `v-for` без `key`, `v-if` на том же элементе |
| `vue/no-ref-as-operand` | `count + 1` вместо `count.value + 1` |
| `vue/no-setup-props-reactivity-loss` | деструктуризация props в `setup` с потерей реактивности |
| `vue/multi-word-component-names` | имя компонента из одного слова (конфликт с HTML-тегами) |
| `@typescript-eslint/no-floating-promises` | Promise без `await` / `.catch` |
| `@typescript-eslint/no-explicit-any` | `any` |
| `vuejs-accessibility/*` | `img` без `alt`, `@click` на `div` без роли и клавиатуры, `label` без поля |
| `import/no-cycle`, `import/order` | циклические зависимости, порядок импортов |
| `eslint-plugin-boundaries` | нарушение границ модулей (FSD, слои) |
| `@tanstack/eslint-plugin-query` | ошибки ключей запросов |
| `@intlify/eslint-plugin-vue-i18n` | захардкоженный текст, отсутствующие ключи перевода |

Type-aware правила (`recommendedTypeChecked`) используют информацию TypeScript и находят больше ошибок, но работают медленнее.

В Nuxt вместо ручной настройки используют модуль `@nuxt/eslint`: он генерирует flat config с учетом авто-импортов и структуры проекта, а `eslint.config.mjs` расширяет его через `withNuxt(...)`.

## Где запускать

- в редакторе (расширение ESLint, для `.vue` — вместе с Vue - Official) — подсветка сразу;
- в pre-commit через lint-staged — только измененные файлы;
- в CI — `eslint . --max-warnings=0` блокирует merge при нарушениях.

## Что важно помнить

- ESLint — про **ошибки и качество**, Prettier — про **форматирование**; конфликты отключает `@vue/eslint-config-prettier/skip-formatting` или `eslint-config-prettier`.
- ESLint не проверяет типы в шаблонах так полно, как `vue-tsc`: оба инструмента нужны.
- `// eslint-disable-next-line rule -- причина` — точечно и с объяснением; в шаблоне — `<!-- eslint-disable-next-line rule -->`.
- Альтернативы: **Biome** (линтер и форматтер на Rust; поддержка `.vue` частичная) и **oxlint** (очень быстрый линтер на Rust, есть правила для Vue; часто используют вместе с ESLint через `eslint-plugin-oxlint` — create-vue предлагает такую опцию).
- Для CSS, в том числе блоков `<style>` в `.vue`, есть Stylelint с `postcss-html`.

## Мини-шпаргалка

ESLint — статический анализ ошибок. ESLint 9: `eslint.config.ts`, массив объектов с `files`, `languageOptions`, `plugins`, `rules`. Для Vue+TS: `defineConfigWithVueTs`, `pluginVue.configs["flat/recommended"]`, `vueTsConfigs.recommended(TypeChecked)`, `vuejs-accessibility`, в конце `skipFormatting`. Nuxt — `@nuxt/eslint`. Запуск: редактор, lint-staged, CI с `--max-warnings=0`.
