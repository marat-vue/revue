# re:vue

Сайт для чтения уроков из родительской папки (`../*.md`) с прогрессом, интервальным повторением FSRS, песочницей и офлайн-режимом (PWA).

**Стек:** Nuxt 4 (статическая генерация) · Vue 3 · TypeScript · Pinia · Tailwind CSS 4 · reka-ui (компоненты в стиле shadcn) · unified/remark/rehype + Shiki · ts-fsrs · sandpack-client + CodeMirror 6 · Workbox.

## Как это устроено

- `server/utils/content.ts` обходит папку конспекта и строит дерево разделов → тем → уроков.
  URL берётся из номеров в именах: `04. JavaScript/01. Основы языка/03. ….md` → `/l/04/01/03/`.
- `server/utils/markdown.ts` превращает markdown в HTML: GFM-таблицы, Obsidian-каллауты (`> [!NOTE]`, сворачиваемые `> [!TIP]-`),
  подсветка кода Shiki с IDE-темами One Light / One Dark Pro (переключаются вместе с темой сайта), переписывание относительных ссылок между заметками.
- Данные страниц отдают серверные маршруты Nitro (`server/api/*`), а `nuxt generate` пререндерит все страницы в статический HTML.
  При переходах внутри сайта данные приходят из `_payload.json` страницы, без запросов к серверу.
- Каждый урок — карточка FSRS: вопрос = заголовок + секция «Вопрос», ответ = каллаут `[!NOTE]`. Все карточки собираются в `/cards.json`.
- Весь прогресс (изученные уроки, карточки, история повторений, настройки) — в Pinia (`app/stores/app.ts`), сохраняется в `localStorage` (`konspekt:v1`)
  плагином `app/plugins/persist.client.ts`. В «Настройках» есть экспорт/импорт JSON.
- Главная: фильтры разделов по направлению, языку и статусу прохождения. Категории и языки разделов задаются в `shared/utils/sections.ts`
  (ключ — название папки без номера; раздел без записи попадает в «Прочее»).
- `/sandbox/` — песочница на Vue (`app/components/sandbox/`): редактор CodeMirror 6, дерево файлов, превью, консоль и панель тестов.
  Код собирает бандлер CodeSandbox через [`@codesandbox/sandpack-client`](https://sandpack.codesandbox.io/docs/advanced-usage/client) в iframe,
  поэтому песочнице нужен интернет. Проекты HTML/CSS, JavaScript, TypeScript, Vue, Canvas, а также тесты (Jest-совместимый раннер,
  Vue Testing Library). Каждый проект сохраняется в `localStorage`. Кнопка ▶ у блоков кода в уроке открывает код
  в проекте «Из урока».
- Живые примеры: блоки кода с мета-флагом `run` (`remarkLiveExamples` в `server/utils/markdown.ts`) превращаются в мини-песочницу прямо
  в уроке (`app/components/lesson/LiveExample.vue`); редактор и бандлер подгружаются только по кнопке «Запустить». Синтаксис — в корневом README.
- Название и описание сайта — в `shared/utils/brand.ts` (шапка, метаданные, манифест).
- PWA: манифест — `server/routes/manifest.webmanifest.get.ts`, иконки — `public/icons` (генерирует `npm run icons`). После `nuxt generate`
  скрипт `scripts/build-sw.mjs` собирает Workbox service worker в `.output/public/sw.js`: оболочка приложения и `cards.json` кешируются заранее,
  страницы и их `_payload.json` — при открытии (NetworkFirst, без сети — `/offline/`). Разделы целиком скачиваются в
  «Настройках → Офлайн и приложение» (`app/utils/offline.ts`). Регистрация и уведомление об обновлении — `app/components/PwaRegister.client.vue`;
  в `npm run dev` service worker не регистрируется.
- id урока — хеш пути **без номеров**, поэтому перенумерация файлов не сбрасывает прогресс (переименование — сбрасывает).

## Команды

```bash
npm install
npm run dev       # http://localhost:3000
npm run build     # статический сайт в .output/public
npm run preview   # раздать .output/public локально
npm run typecheck # проверка типов (vue-tsc)
npm test          # регрессионные тесты импорта, офлайн-загрузки и очереди повторения
npm run check:build # после build: страницы, payload, ресурсы и базовый путь
```

Путь к конспекту можно переопределить переменной `CONTENT_DIR`.

Требуется Node.js 22.12+ или 24+. Команды `build` и `generate` обе создают статический сайт вместе с service worker.
Проверка полноты статического сайта выполняется автоматически в конце сборки. На Windows страницы генерируются последовательно,
чтобы избежать пропусков при конкурентном создании папок; на Linux сохраняется параллельная генерация.
Импорт прогресса проверяет вложенные данные, даты и параметры FSRS до изменения состояния; некорректный файл отклоняется целиком.
Офлайн-раздел считается сохранённым, только когда в кеше есть HTML и `_payload.json` каждой страницы.

В `package.json` закреплены исправленные `glob` и `minimatch` через `overrides`; совместимость проверяется полной сборкой.
На 3 ноября 2026 года `npm audit` остаётся с 8 предупреждениями низкого уровня из одной транзитивной зависимости сборки —
[`deepmerge`, GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Опубликованного исправления пока нет.
Замечаний среднего, высокого и критического уровня нет. На хостинг отправляется только `.output/public`.

## Деплой на GitHub Pages

1. Корень репозитория — папка с уроками, сайт — в `site/`.
2. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
3. Пуш в `main` запускает `.github/workflows/deploy.yml`: он сам подставит `NUXT_APP_BASE_URL=/<repo>`.

Горячие клавиши: `Ctrl K` или `/` — поиск, на экране повторения `Space` — показать ответ / «Хорошо», `1–4` — оценка, `Ctrl Z` — отменить.
