# Компоненты с плагинами: Pinia, Router, provide и custom render

> [!NOTE]
> Компонентам, которые используют Vue Router, Pinia, i18n или `inject`, нужны те же плагины и в тестах. Их передают через опцию `global` (`plugins`, `provide`, `stubs`, `mocks`). Чтобы не повторять настройку в каждом тесте, создают функцию `renderWithPlugins`, которая принимает начальные данные: маршрут, состояние store, пользователя.

## Вопрос

Как тестировать компонент, который использует `useRouter`, `useRoute`, Pinia-store или `inject`?

## Основная идея

Без плагина компонент упадёт или выдаст предупреждение: `injection "Symbol(router)" not found`, `getActivePinia() was called but there was no active Pinia`. Копировать настройку плагинов в каждый тест неудобно, а изменение их состава потребует правки сотен тестов.

Опция `global` у `mount` и `render` настраивает приложение, в котором монтируется компонент:

| Поле | Назначение |
| --- | --- |
| `plugins` | `[router, pinia, i18n]` — то же, что `app.use()` |
| `provide` | значения для `inject`: `{ [ThemeKey]: 'dark' }` |
| `stubs` | заглушки компонентов: `{ RouterLink: RouterLinkStub, Teleport: true }` |
| `mocks` | глобальные свойства шаблона: `{ $t: (key) => key }` |
| `components`, `directives` | глобальная регистрация |

Рекомендованный подход — **custom render**: свой модуль `test/utils`, который реэкспортирует всё из `@testing-library/vue` и добавляет `renderWithPlugins`. Тесты импортируют `render` из `@/test/utils`, а не из библиотеки.

Важные детали:

- **Свежий экземпляр на каждый тест**: новый `createPinia()`, новый `createRouter()`. Иначе состояние и история навигации протекут между тестами.
- **Pinia для тестов**: `createTestingPinia` из `@pinia/testing` заменяет все actions на `vi.fn()` (их можно включить через `stubActions: false`) и принимает `initialState`.
- **Роутер**: в тестах используют `createMemoryHistory()`, затем `router.push(route)` и `await router.isReady()` до монтирования.

Для роутинга удобно монтировать настоящие маршруты: тогда переход проверяется по появлению новой страницы в `<RouterView>`, а не по вызову замоканного `push`.

## Пример

```ts
// src/test/utils.ts
import { render, type RenderOptions } from '@testing-library/vue';
import { createTestingPinia } from '@pinia/testing';
import { createRouter, createMemoryHistory, type RouteRecordRaw } from 'vue-router';
import { routes as appRoutes } from '@/router/routes';

type Options = RenderOptions<unknown> & {
  route?: string;
  routes?: RouteRecordRaw[];
  initialState?: Record<string, unknown>;
};

export async function renderWithPlugins(
  component: unknown,
  { route = '/', routes = appRoutes, initialState = {}, ...options }: Options = {},
) {
  const router = createRouter({ history: createMemoryHistory(), routes });
  const pinia = createTestingPinia({ initialState, stubActions: false, createSpy: vi.fn });

  router.push(route);
  await router.isReady();

  const result = render(component, {
    ...options,
    global: { ...options.global, plugins: [router, pinia, ...(options.global?.plugins ?? [])] },
  });

  return { router, pinia, ...result };
}

export * from '@testing-library/vue';
```

```ts
// AppHeader.test.ts
import { defineComponent, h } from 'vue';
import { RouterView } from 'vue-router';
import userEvent from '@testing-library/user-event';
import { renderWithPlugins, screen } from '@/test/utils';
import AppHeader from './AppHeader.vue';

it('гость видит ссылку «Войти»', async () => {
  await renderWithPlugins(AppHeader, { initialState: { auth: { user: null } } });
  expect(screen.getByRole('link', { name: 'Войти' })).toBeInTheDocument();
});

it('после клика по профилю открывается страница профиля', async () => {
  const user = userEvent.setup();
  const Layout = defineComponent(() => () => [h(AppHeader), h(RouterView)]);
  const routes = [
    { path: '/', component: { template: '<p>Главная</p>' } },
    { path: '/profile', component: { template: '<h1>Профиль</h1>' } },
  ];

  await renderWithPlugins(Layout, {
    routes,
    initialState: { auth: { user: { id: '1', name: 'Анна' } } },
  });

  await user.click(screen.getByRole('link', { name: 'Анна' }));

  expect(await screen.findByRole('heading', { name: 'Профиль' })).toBeInTheDocument();
});
```

Проверка вызова action через `createTestingPinia` со стабами по умолчанию:

```ts
import { mount } from '@vue/test-utils';
import { createTestingPinia } from '@pinia/testing';
import { useCartStore } from '@/stores/cart';

it('вызывает addItem при клике', async () => {
  const wrapper = mount(ProductCard, {
    props: { product: { id: 7, title: 'Чайник' } },
    global: { plugins: [createTestingPinia({ createSpy: vi.fn })] },
  });
  const cart = useCartStore(); // тот же store, что в компоненте

  await wrapper.get('button').trigger('click');

  expect(cart.addItem).toHaveBeenCalledWith(7);
});
```

Простые зависимости без плагинов:

```ts
render(PriceTag, {
  props: { value: 1500 },
  global: {
    provide: { [CurrencyKey]: 'RUB' },
    mocks: { $t: (key: string) => key },
    stubs: { RouterLink: RouterLinkStub },
  },
});
```

## Что важно помнить

- Плагины создаются внутри функции, а не на уровне модуля — иначе состояние общее для всех тестов.
- Возвращайте из `renderWithPlugins` полезные объекты (`router`, `pinia`), чтобы тест мог проверить маршрут или store.
- Шаблоны-строки в `component: { template }` требуют сборку Vue с компилятором: в Vitest задайте alias `vue` → `vue/dist/vue.esm-bundler.js` или используйте `h()` / `.vue`-файлы.
- Для Nuxt-компонентов (`useNuxtApp`, `useFetch`, авто-импорты) используйте `mountSuspended` и `renderSuspended` из `@nuxt/test-utils` в окружении `nuxt`.
- Общие настройки для всех тестов можно задать через `config.global` из `@vue/test-utils` в setup-файле.

## Мини-шпаргалка

Плагины → `global.plugins`. `inject` → `global.provide`. Заглушки → `global.stubs`. Свой `renderWithPlugins` в `test/utils`. Новый router и Pinia на тест. Роутер → `createMemoryHistory` + `await router.isReady()`. Pinia → `createTestingPinia`.
