# Тестирование форм

> [!NOTE]
> Форму тестируют как пользователь: находят поля по label, вводят данные через user-event, отправляют кнопкой и проверяют результат — сообщения об ошибках, событие `submit` (`emitted()`) или запрос с данными, блокировку кнопки и состояние после ответа сервера.

## Вопрос

Что проверять в тесте формы? Как тестировать валидацию и отправку?

## Основная идея

Формы — одно из самых важных мест для тестов: в них сосредоточены валидация, обработка ошибок сервера и состояния загрузки. Тест не должен зависеть от того, как форма реализована: `v-model` с `ref`/`reactive`, VeeValidate, FormKit или компоненты Vuetify. Поэтому взаимодействие идёт через доступные элементы.

Типичный набор сценариев:

| Сценарий | Что проверяем |
| --- | --- |
| Успешная отправка | событие `submit` или запрос с правильными данными, сообщение об успехе |
| Пустые обязательные поля | ошибки видны, отправки нет |
| Невалидный формат | конкретный текст ошибки рядом с полем |
| Исправление ошибки | ошибка исчезает |
| Ошибка сервера | сообщение, введённые данные сохранились |
| Ожидание ответа | кнопка заблокирована, нет двойной отправки |
| Доступность | ошибка связана с полем (`aria-describedby`), `aria-invalid` |

Ошибки удобно искать через `getByRole('alert')` или через связь с полем: jest-dom умеет `toHaveAccessibleDescription` и `toBeInvalid`.

## Пример

```ts
import { render, screen } from '@testing-library/vue';
import userEvent from '@testing-library/user-event';
import SignUpForm from './SignUpForm.vue';

function setup() {
  const user = userEvent.setup();
  // форма принимает асинхронный обработчик через prop, чтобы показывать состояние отправки
  const onSubmit = vi.fn().mockResolvedValue(undefined);
  render(SignUpForm, { props: { onSubmit } });
  return {
    user,
    onSubmit,
    email: screen.getByLabelText('Email'),
    password: screen.getByLabelText('Пароль'),
    submit: screen.getByRole('button', { name: 'Зарегистрироваться' }),
  };
}

it('отправляет корректные данные', async () => {
  const { user, onSubmit, email, password, submit } = setup();

  await user.type(email, 'anna@example.com');
  await user.type(password, 'Secret_123');
  await user.click(submit);

  expect(onSubmit).toHaveBeenCalledWith({ email: 'anna@example.com', password: 'Secret_123' });
});

it('показывает ошибку формата email и не отправляет форму', async () => {
  const { user, onSubmit, email, submit } = setup();

  await user.type(email, 'anna@');
  await user.click(submit);

  expect(email).toBeInvalid();
  expect(email).toHaveAccessibleDescription('Введите корректный email');
  expect(onSubmit).not.toHaveBeenCalled();
});

it('блокирует кнопку на время отправки', async () => {
  const { user, onSubmit, email, password, submit } = setup();
  onSubmit.mockReturnValue(new Promise(() => {})); // запрос «висит»

  await user.type(email, 'anna@example.com');
  await user.type(password, 'Secret_123');
  await user.click(submit);

  expect(submit).toBeDisabled();
});
```

Функция `setup` убирает повторение подготовки, но оставляет каждый тест читаемым.

Если форма сообщает о результате событием (`emit('submit', data)`), проверяют `emitted()`:

```ts
it('отправляет событие submit с данными', async () => {
  const user = userEvent.setup();
  const { emitted } = render(LoginForm);

  await user.type(screen.getByLabelText('Email'), 'anna@example.com');
  await user.click(screen.getByRole('button', { name: 'Войти' }));

  expect(emitted().submit).toEqual([[{ email: 'anna@example.com' }]]);
});
```

Компонент с `v-model` на родителе (`defineModel`) проверяют через событие `update:modelValue`:

```ts
it('обновляет modelValue', async () => {
  const { emitted } = render(EmailInput, { props: { modelValue: '' } });

  await fireEvent.update(screen.getByLabelText('Email'), 'anna@example.com');

  expect(emitted()['update:modelValue']).toEqual([['anna@example.com']]);
});
```

## Что важно помнить

- Если `getByLabelText` не находит поле, label не связан с input — это баг доступности.
- Проверяйте текст ошибки, а не наличие CSS-класса `error`.
- Валидацию схемы (Zod, Yup, Valibot) удобно дополнительно проверить unit-тестами через `it.each`.
- VeeValidate валидирует асинхронно: после ввода и отправки ждите ошибку через `findByText` или `flushPromises`.
- Для формы в Nuxt с `$fetch` или `useFetch` сеть мокают через MSW или `registerEndpoint` из `@nuxt/test-utils`, а связку с сервером проверяют в e2e.
- `user.clear(input)` перед `type` нужен, если в поле есть начальное значение.

## Мини-шпаргалка

Поля → `getByLabelText`. Ввод → `user.type`. Отправка → `user.click(submit)`. Проверки: данные в `onSubmit` или `emitted().submit`, текст ошибки, `toBeInvalid`, `toBeDisabled` во время запроса.
