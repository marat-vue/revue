# Vue Test Utils и Vue Testing Library

> [!NOTE]
> Vue Test Utils (VTU) — официальная библиотека для монтирования Vue-компонентов в тестах: `mount`, `wrapper.find`, `trigger`, `setValue`, `emitted`. Vue Testing Library (VTL) — надстройка над VTU, которая тестирует компонент через DOM так, как с ним работает пользователь: ищет элементы по роли, тексту и label. Главный принцип: чем больше тест похож на использование софта, тем больше уверенности он даёт.

## Вопрос

Что такое Vue Test Utils и Vue Testing Library? Чем они отличаются и что выбрать?

## Основная идея

**Vue Test Utils** — низкоуровневый официальный инструмент. `mount(Component, options)` возвращает `wrapper`, через который можно найти элементы по селектору, найти дочерний компонент (`findComponent`), прочитать props и события, обратиться к экземпляру через `wrapper.vm`. Есть `shallowMount`, который заменяет все дочерние компоненты заглушками (stubs).

**Vue Testing Library** построена поверх VTU и намеренно скрывает `wrapper` и `vm`. Пользователь не знает, что внутри `ref` или `computed`, — он видит кнопку «Оформить» и текст «Итого: 1 500 ₽». Если тест работает с тем же, что видит пользователь, его не нужно переписывать при рефакторинге: переход с Options API на `<script setup>` или вынос логики в composable не ломает тест.

| | Vue Test Utils | Vue Testing Library |
| --- | --- | --- |
| Монтирование | `mount`, `shallowMount` | `render` (внутри — `mount`) |
| Поиск | CSS-селекторы, `findComponent` | роли, текст, label |
| Действия | `trigger`, `setValue` | `fireEvent`, `user-event` |
| Доступ к внутренностям | `wrapper.vm`, `props()` | нет — намеренно |
| Когда удобен | события, слоты, stubs, сложные случаи | поведение глазами пользователя |

На практике их часто совмещают: основная масса тестов пишется в стиле Testing Library, а VTU используют для проверки `emitted()`, stubs и тонкой настройки `global`.

Экосистема Testing Library:

| Пакет | Назначение |
| --- | --- |
| `@vue/test-utils` | `mount`, `shallowMount`, `flushPromises`, глобальная конфигурация |
| `@testing-library/vue` | `render`, `screen`, `fireEvent`, автоматический `cleanup` |
| `@testing-library/user-event` | реалистичная симуляция действий пользователя |
| `@testing-library/jest-dom` | matchers для DOM: `toBeInTheDocument`, `toBeDisabled` |

Тот же подход есть для React, Angular, Svelte и даже Playwright (`getByRole`) — знания переносятся между инструментами.

Побочный эффект философии — **проверка доступности**. Запрос `getByRole('button', { name: 'Сохранить' })` не найдёт `div` с `@click`. Если элемент нельзя найти по роли и имени, скринридер, скорее всего, тоже не сможет его понять.

## Пример

Стиль Testing Library:

```ts
import { render, screen } from '@testing-library/vue';
import userEvent from '@testing-library/user-event';
import Counter from './Counter.vue';

it('увеличивает счётчик по клику', async () => {
  const user = userEvent.setup();
  render(Counter);

  await user.click(screen.getByRole('button', { name: 'Добавить' }));

  expect(screen.getByText('Количество: 1')).toBeInTheDocument();
});
```

Тот же тест на Vue Test Utils:

```ts
import { mount } from '@vue/test-utils';
import Counter from './Counter.vue';

it('увеличивает счётчик по клику', async () => {
  const wrapper = mount(Counter);

  await wrapper.get('button').trigger('click');

  expect(wrapper.text()).toContain('Количество: 1');
});
```

Тест не знает, как реализован `Counter`: через `ref`, `reactive` или Pinia-store. Он проверяет только видимое поведение. А вот так писать не стоит — тест сломается при любом рефакторинге:

```ts
// плохо: проверка внутреннего состояния
expect(wrapper.vm.count).toBe(1);
```

## Что важно помнить

- VTU и VTL — не runner: тесты запускает Vitest (рекомендуется для Vue + Vite) или Jest.
- Для `.vue`-файлов раннеру нужен плагин: в Vitest это `@vitejs/plugin-vue` из `vite.config`.
- `shallowMount` ускоряет тесты, но проверяет компонент в отрыве от детей; по умолчанию лучше `mount` и точечные `stubs`.
- DOM во Vue обновляется асинхронно: после `trigger`, `setValue`, `fireEvent` нужен `await`.
- Если элемент трудно найти по роли или тексту, сначала стоит улучшить разметку, а не добавлять `data-testid`.

## Мини-шпаргалка

VTU = официальный `mount` + `wrapper`. VTL = тест через DOM глазами пользователя поверх VTU. Ищем по роли и тексту, действуем через user-event, проверяем jest-dom. `wrapper.vm` — только в крайнем случае.
