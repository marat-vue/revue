# Тестирование composables

> [!NOTE]
> Composable, который использует только реактивность (`ref`, `computed`, `watch`), тестируют как обычную функцию: вызывают и проверяют возвращённые `ref`. Если composable зависит от жизненного цикла (`onMounted`, `onUnmounted`) или `inject`, его вызывают внутри тестового компонента — через хелпер `withSetup`.

## Вопрос

Как протестировать composable отдельно от компонента? Когда хватит прямого вызова, а когда нужен тестовый компонент?

## Основная идея

В отличие от хуков React, composable во Vue — обычная функция. `ref` и `computed` работают и вне компонента, поэтому composable без хуков жизненного цикла можно просто вызвать в тесте. Возвращённые `ref` живые: после вызова `increment()` значение `count.value` уже обновлено — никакого `act` не нужно.

Нюансы появляются в трёх случаях:

| Composable использует | Что делать в тесте |
| --- | --- |
| только `ref`, `reactive`, `computed` | вызвать напрямую |
| `watch` / `watchEffect` | вызвать напрямую, после изменения — `await nextTick()` (watcher по умолчанию срабатывает перед следующим рендером) |
| `onMounted`, `onUnmounted` | вызвать внутри компонента через `withSetup`, проверять cleanup через `app.unmount()` |
| `inject` | `withSetup` + `app.provide(key, value)` |
| Pinia, Router | `withSetup` + `app.use(pinia)` / замоканный роутер |

`withSetup` — небольшой хелпер из документации Vue: создаёт приложение с компонентом, в `setup` которого вызывается composable, и монтирует его в пустой `div`. Это аналог `renderHook` из React Testing Library.

Если composable создаёт `watch` вне компонента, его эффекты не остановятся сами. Для изоляции можно запустить его в `effectScope()` и вызвать `scope.stop()` после теста.

Когда тестировать composable отдельно: он переиспользуется в нескольких местах, содержит нетривиальную логику (`useDebounce`, `usePagination`, `useLocalStorage`) или является публичным API библиотеки. Если composable используется в одном компоненте, обычно достаточно теста компонента.

## Пример

Прямой вызов:

```ts
import { useCounter } from './useCounter';

it('увеличивает и сбрасывает значение', () => {
  const { count, increment, reset } = useCounter(5);

  expect(count.value).toBe(5);

  increment();
  expect(count.value).toBe(6);

  reset();
  expect(count.value).toBe(5);
});
```

Хелпер `withSetup` для composables с жизненным циклом:

```ts
// src/test/with-setup.ts
import { createApp, type App } from 'vue';

export function withSetup<T>(composable: () => T, configure?: (app: App) => void) {
  let result!: T;
  const app = createApp({
    setup() {
      result = composable();
      return () => {};
    },
  });
  configure?.(app);
  app.mount(document.createElement('div'));
  return [result, app] as const;
}
```

```ts
import { withSetup } from '@/test/with-setup';
import { useWindowWidth } from './useWindowWidth';

it('следит за resize и отписывается при размонтировании', () => {
  const removeSpy = vi.spyOn(window, 'removeEventListener');
  const [width, app] = withSetup(() => useWindowWidth());

  window.innerWidth = 500;
  window.dispatchEvent(new Event('resize'));
  expect(width.value).toBe(500);

  app.unmount();
  expect(removeSpy).toHaveBeenCalledWith('resize', expect.any(Function));
});
```

Смена аргумента и fake timers:

```ts
import { nextTick, ref } from 'vue';
import { useDebouncedRef } from './useDebouncedRef';

it('обновляет значение после паузы', async () => {
  vi.useFakeTimers();
  const source = ref('а');
  const debounced = useDebouncedRef(source, 300);

  source.value = 'анна';
  await nextTick(); // watch внутри composable увидел изменение
  expect(debounced.value).toBe('а');

  vi.advanceTimersByTime(300);
  expect(debounced.value).toBe('анна');
  vi.useRealTimers();
});
```

Composable с `inject`:

```ts
import { ThemeKey } from '@/theme';

it('читает тему из provide', () => {
  const [theme] = withSetup(() => useTheme(), (app) => app.provide(ThemeKey, 'dark'));
  expect(theme.value).toBe('dark');
});
```

## Что важно помнить

- Деструктуризация `const { count } = useCounter()` безопасна, пока `count` — это `ref`: читайте `count.value` после действия. А вот `const value = count.value` до действия сохранит старый снимок.
- Не тестируйте отдельно то, что видно в компоненте, — тест компонента ближе к пользователю.
- `onMounted` вне компонента не вызовется и выдаст предупреждение `onMounted is called when there is no active component instance` — это сигнал использовать `withSetup`.
- Для асинхронного composable: `await flushPromises()` или `await vi.waitFor(() => expect(data.value).toEqual(...))`.
- Composables из VueUse уже покрыты тестами библиотеки — тестируйте свою логику поверх них.

## Мини-шпаргалка

Чистая реактивность → прямой вызов и `.value`. `watch` → `await nextTick()`. Жизненный цикл, `inject`, плагины → `withSetup` + `app.unmount()`. Таймеры → `vi.useFakeTimers()`.
