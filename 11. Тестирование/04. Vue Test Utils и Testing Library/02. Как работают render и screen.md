# render и screen

> [!NOTE]
> `render(Component, { props })` из `@testing-library/vue` монтирует компонент в DOM и возвращает утилиты, включая `rerender` и `unmount`. `screen` — объект со всеми запросами, привязанными к `document.body`. Рекомендуется искать элементы через `screen`, а не через деструктуризацию результата `render`. В Vue Test Utils аналог — `mount`, который возвращает обёртку `wrapper`.

## Вопрос

Что возвращает `render`? Зачем нужен `screen`? Чем `render` отличается от `mount` из Vue Test Utils? Как отладить, что сейчас отрендерено?

## Основная идея

`render` из Vue Testing Library внутри вызывает `mount` из Vue Test Utils: создаёт контейнер `div`, добавляет его в `document.body` и монтирует туда приложение с компонентом. Второй аргумент — те же опции, что у `mount`: `props`, `slots`, `global` (плагины, stubs, provide). Результат содержит:

| Поле | Назначение |
| --- | --- |
| `rerender(props)` | обновить props того же экземпляра |
| `unmount()` | размонтировать — проверка cleanup в `onUnmounted` |
| `container` | DOM-узел, куда смонтирован компонент |
| `baseElement` | корень для запросов, по умолчанию `document.body` |
| `emitted()` | события, которые компонент отправил через `emit` |
| `getByRole` и др. | запросы, привязанные к `baseElement` |

**`screen`** даёт те же запросы, но не требует хранить результат `render`. Код короче и единообразнее. Кроме того, `screen` ищет по всему `document.body`, поэтому находит содержимое `<Teleport to="body">`: модальные окна, тултипы и выпадающие меню, которые рендерятся вне контейнера.

`container.querySelector` — запасной выход. Он возвращает к поиску по классам и тегам, то есть к деталям реализации.

**`render` и `mount`.** `mount` из `@vue/test-utils` возвращает `wrapper` с методами `find`, `findComponent`, `setValue`, `trigger`, `props()`, `emitted()`, `vm`. Это мощно, но поощряет тесты на внутренности: имя дочернего компонента, значение в `vm`. Vue Testing Library намеренно скрывает `wrapper` и оставляет пользовательские запросы. Обе библиотеки совместимы, в одном проекте можно использовать обе.

Для отладки:

- `screen.debug()` печатает текущий DOM;
- `screen.debug(element)` — конкретный узел;
- `screen.logTestingPlaygroundURL()` даёт ссылку на Testing Playground, который подсказывает лучший запрос;
- `logRoles(container)` выводит все доступные роли и имена;
- в Vue Test Utils — `console.log(wrapper.html())`.

## Пример

```ts
import { render, screen } from '@testing-library/vue';
import PriceTag from './PriceTag.vue';
import WindowSize from './WindowSize.vue';

it('обновляет цену при смене props', async () => {
  const { rerender } = render(PriceTag, { props: { value: 1500 } });
  expect(screen.getByText('1 500 ₽')).toBeInTheDocument();

  await rerender({ value: 990 });
  expect(screen.getByText('990 ₽')).toBeInTheDocument();
});

it('отписывается от событий при размонтировании', () => {
  const removeSpy = vi.spyOn(window, 'removeEventListener');
  const { unmount } = render(WindowSize);

  unmount();

  expect(removeSpy).toHaveBeenCalledWith('resize', expect.any(Function));
});
```

Модальное окно через `Teleport`:

```ts
it('открывает модалку', async () => {
  const user = userEvent.setup();
  render(DeleteButton);
  await user.click(screen.getByRole('button', { name: 'Удалить' }));

  // модалка телепортирована в document.body, вне container — screen её находит
  expect(screen.getByRole('dialog', { name: 'Удалить задачу?' })).toBeInTheDocument();
});
```

То же на Vue Test Utils:

```ts
import { mount } from '@vue/test-utils';

it('обновляет цену при смене props', async () => {
  const wrapper = mount(PriceTag, { props: { value: 1500 } });
  expect(wrapper.text()).toContain('1 500 ₽');

  await wrapper.setProps({ value: 990 });
  expect(wrapper.text()).toContain('990 ₽');
});
```

## Попробуйте

Компонент и тесты в стиле Vue Testing Library: `render` монтирует компонент, `screen` ищет элементы так, как их видит пользователь.

```vue run=vtl file=Greeting.vue
<script setup lang="ts">
import { ref } from "vue";

const name = ref("");
</script>

<template>
  <form @submit.prevent>
    <label>
      Имя
      <input v-model="name" />
    </label>
    <h2>{{ name ? `Привет, ${name}!` : "Как вас зовут?" }}</h2>
  </form>
</template>
```

```ts run=vtl file=Greeting.test.ts
import { render, screen, fireEvent } from "@testing-library/vue";
import Greeting from "./Greeting.vue";

describe("Greeting", () => {
  it("показывает вопрос, пока имя не введено", () => {
    render(Greeting);
    expect(screen.getByRole("heading").textContent).toBe("Как вас зовут?");
  });

  it("здоровается после ввода имени", async () => {
    render(Greeting);
    await fireEvent.update(screen.getByLabelText("Имя"), "Анна");
    expect(screen.getByRole("heading", { name: "Привет, Анна!" })).toBeTruthy();
  });
});
```

## Что важно помнить

- Для компонентов, которым нужны плагины (роутер, Pinia, i18n), передают `global: { plugins: [...] }` или создают свою функцию `renderWithPlugins`.
- Обновления DOM во Vue асинхронные: после изменения состояния нужен `await` — у `fireEvent`, `rerender`, `setProps`, `trigger` или `nextTick()`.
- Vue Testing Library сама вызывает `cleanup` после каждого теста, если в раннере включены globals.
- `within(element)` ограничивает поиск частью DOM: например, конкретной строкой таблицы.

## Мини-шпаргалка

`render(Comp, { props, slots, global })` → монтирование + `rerender` / `unmount` / `emitted`. Запросы → `screen.*` (видит Teleport). Часть DOM → `within`. После изменений → `await`. Отладка → `screen.debug()`, `logRoles`.
