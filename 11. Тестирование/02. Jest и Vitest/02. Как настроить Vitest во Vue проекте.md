# Настройка Vitest во Vue-проекте

> [!NOTE]
> Для тестов Vue-компонентов нужны Vitest, плагин `@vitejs/plugin-vue` (чтобы раннер понимал `.vue`-файлы), DOM-окружение (jsdom или happy-dom), Vue Test Utils и/или Vue Testing Library, user-event и jest-dom. Окружение и setup-файл задаются в конфиге Vitest. Шаблон `npm create vue@latest` настраивает всё это при выборе Vitest.

## Вопрос

Как с нуля настроить тестирование Vue-компонентов в проекте на Vite?

## Основная идея

Компоненты рендерятся в DOM, а Node.js его не имеет. Поэтому указывают окружение `jsdom` — JavaScript-реализацию DOM. Single File Components (`.vue`) раннер компилирует тем же плагином `@vitejs/plugin-vue`, что и dev-сервер, поэтому `<script setup>`, `lang="ts"` и scoped-стили работают без отдельного трансформера (в Jest для этого нужен `@vue/vue3-jest`).

Для монтирования компонентов ставят `@vue/test-utils`. Для запросов в стиле пользователя — `@testing-library/vue` (она использует VTU внутри), для реалистичных действий — `@testing-library/user-event`, для читаемых проверок вроде `toBeInTheDocument` — `@testing-library/jest-dom`.

**Setup-файл** выполняется перед каждым тестовым файлом. В нём подключают matchers jest-dom, запускают MSW-сервер, задают общую конфигурацию Vue Test Utils (`config.global`) и добавляют заглушки браузерных API, которых нет в jsdom.

Опция `globals: true` делает `describe`, `it`, `expect`, `vi` глобальными, как в Jest. Она же позволяет Vue Testing Library автоматически вызывать `cleanup` после каждого теста: библиотека регистрирует его через глобальный `afterEach`.

## Пример

```bash
npm install -D vitest jsdom @vue/test-utils @testing-library/vue @testing-library/user-event @testing-library/jest-dom
```

Обычно конфиг тестов объединяют с `vite.config.ts`, чтобы переиспользовать плагины и алиасы:

```ts
// vitest.config.ts
import { fileURLToPath } from 'node:url';
import { defineConfig, mergeConfig } from 'vitest/config';
import viteConfig from './vite.config';

export default mergeConfig(
  viteConfig,
  defineConfig({
    test: {
      environment: 'jsdom',
      globals: true,
      root: fileURLToPath(new URL('./', import.meta.url)),
      setupFiles: ['./src/test/setup.ts'],
      restoreMocks: true,
    },
  }),
);
```

```ts
// vite.config.ts
import { fileURLToPath, URL } from 'node:url';
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
});
```

```ts
// src/test/setup.ts
import '@testing-library/jest-dom/vitest';
import { config } from '@vue/test-utils';

// глобальные заглушки для всех тестов
config.global.stubs = { teleport: true };
```

```json
// tsconfig.vitest.json (фрагмент)
{
  "extends": "./tsconfig.app.json",
  "compilerOptions": {
    "types": ["node", "jsdom", "vitest/globals", "@testing-library/jest-dom"]
  }
}
```

```ts
// src/components/Greeting.test.ts
import { render, screen } from '@testing-library/vue';
import Greeting from './Greeting.vue';

it('приветствует пользователя по имени', () => {
  render(Greeting, { props: { name: 'Анна' } });
  expect(screen.getByRole('heading', { name: 'Привет, Анна!' })).toBeInTheDocument();
});
```

```json
// package.json (фрагмент)
{
  "scripts": {
    "test:unit": "vitest",
    "type-check": "vue-tsc --build"
  }
}
```

## Что важно помнить

- `restoreMocks: true` восстанавливает моки и шпионов перед каждым тестом — меньше утечек между тестами.
- `happy-dom` — более быстрая, но менее полная альтернатива jsdom.
- В jsdom нет `matchMedia`, `IntersectionObserver`, `ResizeObserver`, `scrollTo` — их мокают в setup-файле. Это особенно важно для Vuetify и composables из VueUse.
- Vitest не проверяет типы в `.vue`-файлах — для этого отдельно запускают `vue-tsc`.
- Для Nuxt-проекта используют `@nuxt/test-utils` и `environment: 'nuxt'`: так в тестах работают авто-импорты, `useNuxtApp` и `mountSuspended`.

## Мини-шпаргалка

vitest + `@vitejs/plugin-vue` + jsdom + Vue Test Utils / Vue Testing Library + user-event + jest-dom. Конфиг: `mergeConfig(viteConfig, …)`, `environment: 'jsdom'`, `globals`, `setupFiles`. Setup: matchers, MSW, `config.global`, заглушки API.
