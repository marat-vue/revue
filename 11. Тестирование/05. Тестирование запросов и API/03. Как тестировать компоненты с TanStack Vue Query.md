# Тестирование компонентов с TanStack Vue Query

> [!NOTE]
> Компоненты с `useQuery` и `useMutation` из `@tanstack/vue-query` тестируют с настоящим QueryClient и MSW. Для каждого теста создаётся новый QueryClient с `retry: false` и подключается плагином `VueQueryPlugin`, чтобы кеш не протекал между тестами, а ошибки появлялись сразу.

## Вопрос

Как тестировать Vue-компонент, использующий TanStack Query? Нужно ли мокать `useQuery`?

## Основная идея

Мокать `useQuery` через `vi.mock` — плохая идея. Тест не проверит ключи запросов, `select`, обработку ошибок, инвалидацию после мутации и оптимистичные обновления. А это как раз то, где чаще всего ошибаются. Поэтому библиотеку оставляют настоящей, а сеть мокают MSW.

Во Vue QueryClient передаётся не провайдером, а плагином: `app.use(VueQueryPlugin, { queryClient })`. В тесте — через `global.plugins`.

Особенности тестовой настройки:

- **новый QueryClient на тест** — общий клиент хранит кеш, и второй тест получит данные первого без запроса;
- **`retry: false`** — по умолчанию TanStack Query повторяет упавший запрос 3 раза с задержкой, тест ошибки будет долгим или упадёт по таймауту;
- **`gcTime: Infinity`** иногда задают, чтобы не оставалось таймеров сборки мусора после теста.

Мутации проверяют по результату: после `useMutation` и `invalidateQueries` список должен перезапроситься и показать новый элемент. Оптимистичное обновление проверяют так: элемент появляется до ответа сервера, а при ошибке — откатывается.

## Пример

```ts
import { QueryClient, VueQueryPlugin } from '@tanstack/vue-query';
import { render, screen } from '@testing-library/vue';
import userEvent from '@testing-library/user-event';
import { http, HttpResponse, delay } from 'msw';
import { server } from '@/test/server';
import TodoList from './TodoList.vue';

function renderWithClient(component: unknown) {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false }, mutations: { retry: false } },
  });
  return render(component, {
    global: { plugins: [[VueQueryPlugin, { queryClient }]] },
  });
}

it('добавляет задачу и обновляет список', async () => {
  let todos = [{ id: '1', title: 'Купить хлеб', done: false }];
  server.use(
    http.get('/api/todos', () => HttpResponse.json(todos)),
    http.post('/api/todos', async ({ request }) => {
      const { title } = (await request.json()) as { title: string };
      todos = [...todos, { id: '2', title, done: false }];
      return HttpResponse.json(todos.at(-1), { status: 201 });
    }),
  );
  const user = userEvent.setup();
  renderWithClient(TodoList);

  expect(await screen.findByText('Купить хлеб')).toBeInTheDocument();

  await user.type(screen.getByLabelText('Новая задача'), 'Позвонить маме');
  await user.click(screen.getByRole('button', { name: 'Добавить' }));

  // после invalidateQueries список перезапрашивается
  expect(await screen.findByText('Позвонить маме')).toBeInTheDocument();
});

it('откатывает оптимистичное обновление при ошибке', async () => {
  server.use(
    http.patch('/api/todos/:id', async () => {
      await delay(50);
      return new HttpResponse(null, { status: 500 });
    }),
  );
  const user = userEvent.setup();
  renderWithClient(TodoList);

  const checkbox = await screen.findByRole('checkbox', { name: 'Купить хлеб' });
  await user.click(checkbox);
  expect(checkbox).toBeChecked(); // оптимистично

  expect(await screen.findByRole('alert')).toHaveTextContent('Не удалось сохранить');
  expect(checkbox).not.toBeChecked(); // откат
});
```

Переменная `todos` внутри теста работает как маленький fake-сервер: GET возвращает актуальное состояние после POST.

Composable поверх `useQuery` тестируют через хелпер `withSetup` (см. урок про composables), подключив плагин в `configure`:

```ts
it('useTodos загружает задачи', async () => {
  const queryClient = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  const [result] = withSetup(() => useTodos(), (app) => app.use(VueQueryPlugin, { queryClient }));

  await vi.waitFor(() => expect(result.isSuccess.value).toBe(true));
  expect(result.data.value).toHaveLength(1);
});
```

## Что важно помнить

- Не создавайте QueryClient на уровне модуля в тестах.
- Ключ запроса во Vue может быть реактивным (`['todos', page]`, где `page` — `ref`): проверьте, что смена `page` вызывает новый запрос.
- Если библиотека пишет ошибки запросов в консоль, это не повод их скрывать глобально — шпионьте точечно.
- Pinia Colada (`useQuery` от команды Pinia) тестируется по тому же принципу: настоящая библиотека, свежая Pinia на тест, сеть через MSW.
- В Nuxt для `useFetch` и `useAsyncData` используют `mountSuspended` и `registerEndpoint` из `@nuxt/test-utils`.

## Мини-шпаргалка

Настоящий QueryClient + MSW, `useQuery` не мокаем. Новый клиент на тест, `retry: false`, подключение через `global.plugins: [[VueQueryPlugin, { queryClient }]]`. Мутации и оптимистичные обновления — по видимому результату.
