# Тестирование Pinia и глобального state

> [!NOTE]
> Pinia-store тестируют двумя способами: логику — напрямую, создав свежую Pinia через `setActivePinia(createPinia())` в `beforeEach`, связку с UI — через рендер компонента с `createTestingPinia` или настоящей Pinia. Главное правило — новый экземпляр Pinia на каждый тест, иначе состояние протечёт между тестами.

## Вопрос

Как тестировать Pinia-store? Нужно ли мокать store в тестах компонентов?

## Основная идея

Store, объявленный через `defineStore`, хранит состояние не в модуле, а в активном экземпляре Pinia. Поэтому изоляция тестов сводится к одной строке: перед каждым тестом создаём новую Pinia и делаем её активной. Второй тест не увидит товары, добавленные первым.

**Тест логики store** не требует компонентов: вызываем action и проверяем `state` и `getters`. Это быстрые unit-тесты для расчётов, переходов состояния и граничных случаев. Для setup-store (функция с `ref` и `computed`) подход тот же.

**Тест компонента** монтирует компонент с Pinia в `global.plugins`. Есть два варианта:

| Вариант | Actions | Когда использовать |
| --- | --- | --- |
| `createPinia()` | настоящие | интеграционный тест: компонент + store вместе |
| `createTestingPinia()` из `@pinia/testing` | заменены на `vi.fn()` (по умолчанию) | проверить, что компонент вызвал action и правильно показал заданное состояние |

`createTestingPinia({ initialState: { cart: { items: [...] } } })` задаёт начальное состояние по id store. Опция `stubActions: false` оставляет actions настоящими. Getters в testing-pinia можно переопределить присваиванием: `cart.total = 999` (в TypeScript понадобится `// @ts-expect-error`).

Мокать сам модуль store через `vi.mock` не нужно — иначе тест не заметит ошибок в getters и actions.

**Store без Pinia.** Простой глобальный state на `reactive()` в модуле — синглтон: его нужно сбрасывать вручную в `beforeEach` или экспортировать фабрику. Vuex (legacy) тестируют похоже на Pinia: новый `createStore(options)` на каждый тест, мутации — как чистые функции.

## Пример

```ts
// stores/cart.ts
import { defineStore } from 'pinia';

type Item = { id: string; price: number; qty: number };

export const useCartStore = defineStore('cart', {
  state: () => ({ items: [] as Item[] }),
  getters: {
    total: (state) => state.items.reduce((sum, i) => sum + i.price * i.qty, 0),
    count: (state) => state.items.reduce((sum, i) => sum + i.qty, 0),
  },
  actions: {
    add(item: Omit<Item, 'qty'>) {
      const existing = this.items.find((i) => i.id === item.id);
      if (existing) existing.qty++;
      else this.items.push({ ...item, qty: 1 });
    },
  },
});
```

```ts
// stores/cart.test.ts
import { setActivePinia, createPinia } from 'pinia';
import { useCartStore } from './cart';

beforeEach(() => setActivePinia(createPinia()));

it('увеличивает количество при повторном добавлении', () => {
  const cart = useCartStore();
  cart.add({ id: '1', price: 500 });
  cart.add({ id: '1', price: 500 });

  expect(cart.items).toEqual([{ id: '1', price: 500, qty: 2 }]);
  expect(cart.total).toBe(1000);
});
```

```ts
// CartBadge.test.ts
import { render, screen } from '@testing-library/vue';
import { createTestingPinia } from '@pinia/testing';
import CartBadge from './CartBadge.vue';

it('показывает количество товаров из store', () => {
  render(CartBadge, {
    global: {
      plugins: [
        createTestingPinia({
          createSpy: vi.fn,
          initialState: { cart: { items: [{ id: '1', price: 500, qty: 3 }] } },
        }),
      ],
    },
  });
  expect(screen.getByText('В корзине: 3')).toBeInTheDocument();
});
```

Проверка вызова action:

```ts
import { mount } from '@vue/test-utils';
import { createTestingPinia } from '@pinia/testing';
import { useCartStore } from '@/stores/cart';
import BuyButton from './BuyButton.vue';

it('кнопка добавляет товар в корзину', async () => {
  const wrapper = mount(BuyButton, {
    props: { product: { id: '1', price: 500 } },
    global: { plugins: [createTestingPinia({ createSpy: vi.fn })] },
  });
  const cart = useCartStore();

  await wrapper.get('button').trigger('click');

  expect(cart.add).toHaveBeenCalledWith({ id: '1', price: 500 });
});
```

## Что важно помнить

- `setActivePinia(createPinia())` в `beforeEach` — для unit-тестов store; в тестах компонентов Pinia передают через `global.plugins`.
- Опция `createSpy: vi.fn` нужна, если в Vitest не включены `globals`.
- С плагином `pinia-plugin-persistedstate` очищайте `localStorage`, иначе состояние восстановится из хранилища.
- Store, который использует другой store, получает его из той же активной Pinia — мокать зависимый store не нужно.
- Не тестируйте `$reset`, `$patch` и реактивность Pinia — это код библиотеки.

## Мини-шпаргалка

Логика → `setActivePinia(createPinia())` в `beforeEach`, вызов action, проверка state и getters. UI → `global.plugins: [createTestingPinia({ initialState })]`. Проверка вызова → actions-стабы testing-pinia. Настоящие actions → `stubActions: false`.
